# 公開ブラウザ制作台（v1）

## 303／909のまとめ操作・音色の場面（2026-10-23）

「元の303×2＋909」の **響きをまとめて遊ぶ**。新しい音源は足さず、同じ楽器のパラメータを動かす。

1. **硬さ／うねり／空間** の3本を動かす。硬さは303のcutoff 20〜80・reso 2〜10、キックattack 20〜70・スネアsnappy 20〜80。うねりは303 env 20〜80・decay 15〜70、閉ハットdecay 15〜55・開ハット20〜65。空間は2台の303のdelayWet 0〜40。割合表示は操作範囲の目安で、個別調整後は対象の平均値。
2. **保存先**でA〜Hを選び、名前を付けて **今の音色を保存**。保存先を選ぶだけでは音は変わらない。上のA〜Hボタンは呼び出し専用で、空は無効。停止中はすぐ、演奏中は次の小節の頭へ予約する。呼び出し後に音色を触ると **編集あり** を表示する。上書きは保存ボタンを押した瞬間の名前と音色を切り取り、確認して保存する。その間にAUTOや手操作で音が進んでも、保存が現在の演奏を書き戻すことはない。保存先を空にする操作も確認して実行。
3. 2つ以上保存したら **場面AUTO**。4／8／16小節ごとに保存した場面をA→H順で巡る。従来の303／909 AUTOとは切り替えて使う。音符・打点・音量・BPMは動かさず、固定パートを守る。ドラッグ中は待機し、離した後は新しい間隔を数える。手動操作で切替予約を解除し、STOPでも予約を破棄する。SONGでは使わない。
4. 個別フェーダーは固定中も操作できる。まとめ操作・場面は固定中の楽器へ書き込まない。303のwaveformと露出済み音色、909の高さ・硬さ・余韻等を保存し、音符／打点・パート音量・テンポ・固定状態・Strudel本体は場面に含めない。音色変化の聴感音量は自動補正しない。

場面棚はブラウザの `music-workbench-rack-tone-scenes-v1`。同じ端末・同じ配信元の単独／埋込ラックで共用し、別のFILEでも音色を使える。Strudelとの **組み合わせを保存**、録音開始時の設定JSON、既存バックアップへも場面棚とAUTO設定を含める。machine v3／backup schema 4の任意拡張で、旧バックアップを開いても現在の場面棚は消さない。旧アプリは場面情報を保持できないため、読み込み前にアプリ更新を行う。単独FILEは現在のフレーズと音色のみ。

保存失敗は棚を置き換えず通知。別画面の更新と競合した場合は上書きせず、組み合わせ／JSONを保管して開き直す。明示的な組み合わせ復元では場面を画面へ適用し、保存できなければその旨を案内する。壊れた端末棚を消さない。音の時計・音源・依存は増やさず、既存schedulerのtickから場面を切り替える。新規の音声ファイルは0。本人の聴感と実iPhone操作は別途確認する。

## 歌詞を見ながら声を録る（2026-10-13）

既存の試奏台／元の303×2＋909、どちらも上の **歌詞・録音** から。同じブラウザなら同じテイク棚を使う。

1. 好きな303とキックを固定して再生。語りはビートの半分の速さで大きく数え、返しの303を少し下げ、AUTOを8小節にすると声の間を取りやすい。
2. **歌詞を選ぶ → 残響の住所（内蔵）**。スマホでもTXTの読み込みは不要。自分で書く時は **自分の下書き**。切替前の編集と名前は各選択肢に別々に保存し、選び直すと戻る。従来の歌詞は自分の下書きへ引き継ぐ。手持ちのTXTは任意で末尾へ追加できる。
3. 選択のすぐ下の **歌詞を大きく表示**。この画面の **マイク・録音の準備** から、有線ヘッドホンで **マイクを準備** → ブラウザの許可 → メーター確認。声はスピーカーへ返さない。演奏だけなら **録音するもの → 演奏だけ（マイク不要）**。マイク未準備の声録音は開始できない。
4. **録音開始**。準備欄がたたまれ、歌詞を広く読める。指でスクロール、または上の **読む場所** でIntro／Verse／前後のHookへ移動。録音開始／停止と経過時間は下端に残る。**編集・演奏に戻る** でも録音は続き、AUTO・dice・faderで遊べる。文章を直す時は **歌詞・名前を編集**。録音中は歌詞の切替・編集を止め、開始時の歌詞をテイクへ残す。入力／Bluetooth遅延は補正しない。自分で入りを数え、最大5分、終わったら **録音を終える**。
5. 録音後の **録ったテイクを確認 ↓** で、今録ったテイクへ移動。**聴く音 → ミックス音声／声だけ／演奏だけ** を選び、**テイクを聴く**。試聴すると現在の演奏とマイクを止める。音の切替は先頭から、**棚を更新** では試聴位置を保つ。演奏だけで録ったテイクには声の選択肢は出ない。声だけは声faderより前の入力、mixは余裕を持たせる固定gain 0.7（リミッターではない）。各音声の音量はそろえていない。
6. **歌詞へ戻る・次のテイク** で今の歌詞を開く。前のテイクは残り、録音や演奏は自動開始しない。歌詞画面の **演奏を再開** で今のフレーズ・音色を鳴らし、声を録るならマイクを準備し直す。Strudel単独／同期演奏／元の303・909単独の今の接続を使う。試聴のための停止では元機材の画面と未保存の調整を保持する。録音は別の明示操作で、演奏停止中・準備中は開始できない。**演奏を止める** で準備中の再生も取り消せる。録音中はこの演奏操作を無効にし、まず録音を終える。**音声・歌詞・演奏設定を取り出す** から各音声／歌詞TXT／演奏設定JSONを保管。実際の録音形式に応じてwebm／m4a／oggを付ける。設定JSONは既存「持ち運び・バックアップ」へ読み込み、開始時のフレーズ・音色・固定・AUTO・コードを下書きへ追加できる。演奏中の操作履歴／進行位置ではない。各音声の開始位置はDAW等で微調整が必要。

録音はIndexedDBのこの端末だけ。12件／250 MB、1件5分／40 MBまで。満杯なら削除せず案内し、保存失敗時は画面内に音声を保持して手動ダウンロードを促す。公開・送信しない。通常のbackup JSONは録音・歌詞を含まない。サイトデータを削除するとテイクも消える。背景化・音声中断・mic切断で録音終了。実iPhone／実マイクの収録、長時間負荷、声の聴感は本人の端末で確認する。

元機材の出力／Strudelのpinned controller出力から録音専用の分岐を作り、既存のclock・出力先を変更しない。停止後は分岐とmic trackのみ解放する。録音用メーター／状態確認の150ms pollは音楽clockを動かさない。新規ライブラリ・音源なし。

内蔵の「残響の住所」初稿は、2026-10-12の本人依頼による公開例外。`src/vocal-lyrics.js`だけに収録しPWAの同じ世代へ含める。個人の編集やテイクは送信しない。従来v1保存キーは移行後も消さず、v2で選択曲別の編集を管理する。自動スクロール／歌詞追従は行わない。

複数タブでは保存時に最新の歌詞棚を読み、別曲の編集を残す。同じ曲が別画面で変更されていたら上書きと切替を止める。警告が出た時は、今の文章を **歌詞TXTを保存** してから開き直す。保存失敗・編集競合が残る間はページを閉じる時にも警告する。手持ちの歌詞は行単位の `[Verse]` 等を「読む場所」に使える。

開発検証: `tests/fixtures/vocal-review.html`はworkbench/v1をローカル配信して開き、合成音の3系統を端末棚へ保存して試聴切替・棚更新・歌詞へ戻る操作を確認する。公開buildには含めない。`tests/vocal-recorder.test.mjs`は失敗と解除を含むライフサイクル。`tests/fixtures/vocal-browser.html`をローカルdistへ一時コピーすると実MediaRecorderの3系統を140Hz／700Hzで検証できる。マイク権限・外部音源なし。このfixtureは公開build／PWAに含めない。MediaRecorderは[対応形式を実行時に判定](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)、[マイクはユーザー許可とsecure contextが必要](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

## 固定を残してAUTOで遊ぶ（2026-10-12）

1. 好きな303とキックを固定し、**303／909 AUTO · OFF**を押してONにする。**4小節**が標準、2／8／16小節にも変えられる。
2. **RUN**（同期画面は**一緒に再生**）で開始。鳴っている未固定パートだけを、アクセント・スライド・裏拍・音色で少しずつ変える。前の変化は次の区切りで元のモチーフへ戻り、音数を増やし続けない。音量・BPM・無音パートはそのまま。
3. 演奏中にサイコロ／フェーダー／元画面のパッドで触ると、その音を新しい基準にする。ドラッグ中は自動変更を待ち、操作後は次の区切りを待つ。固定を追加したパートも以後保護。AUTO OFFは今の形をキープ、停止中は進まない。
4. **組み合わせを保存**でAUTOのON/OFF・間隔・今のフレーズも保存する。開くと停止状態、再生してから新しい小節数を数える。再生位置や変奏履歴は保存しない。機材snapshot v3／backup schema 4。旧snapshot 1／2、backup 1／2／3はAUTO OFFで読み込む。FILE単体の形式は維持し、AUTOはブラウザ設定にも残る。

**打ち替えの使い分け:** 音色の調整はラックの楽器選択とフェーダー。打点／303の音程・アクセント・スライドの直接編集は「元の操作画面へ」で16ステップを使う。「モジュールで遊ぶ」で戻っても同じ演奏が続く。固定は自動変更から守るだけなので手編集できる。SONGは元画面で編集し、AUTOはPATTERN専用。Strudel側のLIVE自動展開とは別の操作で、同期時も時計は共通。

## 909のパートを固定して遊ぶ（2026-10-12）

1. 909カードで **キックを固定**。キックの打点・アクセント・音色がサイコロから守られる。
2. **🎲 スネアだけ**／**🎲 ハットだけ**で、そのパートだけ変える。ハットは閉／開のうち固定していない方を変える。他の303・ドラム・全音量・BPMは維持。
3. **全11パート・固定・サイコロ候補**を開くと、各行に固定と🎲。909全体の固定中は個別サイコロも止まる。固定中でも手動フェーダーは使える。
4. **組み合わせを保存**で、パート固定もStrudelと一緒に残す。古い組み合わせは個別固定なしで開く。バックアップはschema 4（1／2／3の読込も可）。古いアプリで新しいJSONを読むと拒否し、固定を黙って捨てない。

「基本4パートを組む」も固定中の打点を保つ。候補チェックはサイコロの候補、固定は今の打点・音色の保護で、ミュートではない。個別🎲で指定した未選択パートは候補にも加える。全体／909だけ／元の操作画面のサイコロにも個別固定が効く。戻り先や保存版を明示的に開く操作は、選んだ版を復元する。

単独モジュールの固定は同じブラウザの設定にも残る。FILEの音符・音色形式は変えず、固定まで作品として持ち運ぶには組み合わせのJSONを使う。


## Strudelと元の303／909を一緒に鳴らす（2026-10-12）

- 既存試奏台の上の「一緒に鳴らす」→「一緒に再生」。PCはStrudelと元の機材を左右に、スマホは縦に並べる。
- 元の全画面では「Strudelと一緒に」。現在の16パターン・選択パターン・楽器の固定を同じタブ内で持ち込み、アンビエントのStrudelを添える。移動だけでは発音せず、明示再生を待つ。FILEの上書きはしない。
- 303低音／返し／909の「固定」はサイコロからその楽器を守る。固定中も手動フェーダーは効く。Strudel LIVEの固定とサイコロはStrudel側だけに作用する。
- BPMはStrudelで変更。右の303／909全体音量は55%から開始。左のStrudel音量とは別。低音・キックを重ねすぎたら片方を下げる。音量補正や総合リミッターではない。
- 全停止・Escで双方を停止。機材のフレーズを残して再開できる。同期モードを解除すると両方停止し、元の機材のデータは保持する。
- **まとめて保存**：「組み合わせを保存」→名前→保存。Strudelコード、303／909の全16パターン・音色・固定・打楽器候補、混ぜ具合が1件になる。上の「組み合わせを開く」で選ぶと停止状態で復元。「選んだ保存版へ戻す」で、いじった後も同じ版に戻せる。同期中は左の「保存」も同じ操作。
- 保存先はこの端末・ブラウザ。JSONバックアップにも含まれる（組み合わせ入りはschema 3、従来のみならschema 1）。音源ファイル・演奏位置・一時戻り先は含まない。旧コード下書き／機材FILEは保持し、復元時に既存FILEを上書きしない。音符のStrudel変換・自由配線は未実装。

同時演奏は`?stage=ambient&link=1`でも開ける。普段の入口は既存Listen。音源・新規hosting・依存の追加なし。

実装：`machine-clock.js`は実Strudel schedulerに無音の16分音符を重ね、その発音時刻で元のAudioEngineを駆動する。元の独立clockは起動しない。AudioContextも親から共有し、BPM・小節・停止を合わせる。303の音程関係・アクセント・スライド・元のrandomizer／FILE schemaは維持する。再開時は旧発音先を切断して新しいvoice busへ替え、予約済みの古い音を混ぜない。4同梱WAVのdecode結果は同じ接続内で再利用する。

画面切替でiframeを移動しない。Strudelの固定版ビルドには`synth-only`要素だけ再接続時に既存Mirrorを保つガードを加え、コード／schedulerの二重生成を防ぐ。元dependencyは変更せずSHAを検査する。旧単独モードの時計と通常の初期化は保持する。実機iPhone・本人の聴感・長時間背景再生は別途確認。


## 元の303をモジュールで遊ぶ（2026-10-12）

普段の入口は [Listen](https://music-stack.pages.dev/listen.html) → 試奏台 → **元の303×2＋909**。
「全画面で開く」でPCは低音・返し・ドラムを横に並べ、スマホは縦に並べる。
元のacidBros音源とサイコロを使う3枚の操作面で、3台は同じ時計・出力で鳴る。

1. **RUN**で演奏。**🎲 組み合わせ**で音程・アクセント・スライド・ドラム・音色を組み替える。
2. 好きな低音が出たら、そのカードを**固定**。返しやドラムの**🎲 この楽器だけ**で続きを探す。
3. フェーダーで**音量／明るさ／みょん／うねりの深さ・長さ／残響**を演奏中にも変更。固定はサイコロとAUTOに効き、手では触れる。
4. 909は**基本4パートを組む**でキック・スネア・閉／開ハットの打点を配置。固定中は解除してから操作する。既存の打点を置き換えるが、音色・音量・303は保持する。**全11パート・固定・サイコロ候補**で各楽器の打点数／音量／無音を確認し、候補を追加。候補だけで打点は増えず、音量0なら手で上げる。打楽器の選択欄は**音色の編集対象で、ソロではない**。11パートは打点があれば同時に鳴る。打楽器を選んで高さや余韻を調整。**打楽器を追加 → 選択 → APPLY**でサイコロ候補を増やす。選択だけで打点は増えない。元のサイコロには、候補表示外のシンバルが入る場合もある。
5. **ここを戻り先に**で現在のパターンを一時保持。試してから**戻り先へ戻す**。サイコロと戻す操作は現在の各音量・BPMを保つ。
6. 気に入ったら**FILE · 保存／開く → SAVE**で端末に残す。戻り先はFILE保存ではなく、パターンやFILEを替えると消える。

明るさはフィルターの開き、みょんは共鳴、うねりはフィルターの変化量と減衰、残響はディレイ量。
数字は元のつまみと同じ単位で、Hzや秒ではない。音量0は以後の発音を抜く操作で、既に出た残響は残る。
低音は元の303の2号機、返しは1号機。サイコロは低音を元に返しの音程を選ぶ。
**元の操作画面へ**で16ステップ、16パターン、SONG、ドラム音源編集へ戻れる。画面を替えても同じ演奏。
SONGの編集は元の画面で行い、モジュール側の音色・サイコロはPATTERN時のみ操作する。

この3台はacidBrosの音源を使う。単独でも、上記「一緒に鳴らす」でStrudelと同期しても使える。
音符の相互変換、自由なケーブル配線、モジュール数の無制限追加は未実装。
操作面は`src/machine-rack/`、ビルド時に既存acidBrosへ差し込む。音源・追加サンプル・依存・新しい音声clockは増やさない。

## 単曲棚のジャンルとアーカイブ

単曲棚は10試作（通常6／ミニマルテクノ1／アーカイブ3）。ジャンルと「試作」を表示し、推定ジャンルには説明を添える。アーカイブも一覧から選び直してコードを開き、明示Playで再訪できる。旧ID・default・保存／下書きの互換と、A/B・LIVE素材8件は保持する。

「Minimal Techno 01・小さな変化」は124 BPM・32小節（約61.94秒）の短い合成試作。[作品の直リンク](https://music-private-live-workbench.pages.dev/?work=minimal-techno-01)はPlay・Stopのある操作欄から開く。Playで聴き、すぐ下の「この試作の音量」LEVELで調整する。最初はキックだけで、約8秒で3パートが揃う。既定は「1回（ループOFF）」。続け方を選ぶと、選択中のモードの長さと繰り返し方を表示する。

| 再生モード | 流れ |
|---|---|
| 1回（ループOFF） | 32小節で発音終了。再生表示は自動Stopしないので、終了後はStopを押す |
| 固定ループ | 同じ32小節を繰り返す |
| 自動展開 | 16小節×4章でハットを抜く・ベースの明るさを下げる・キックを間引く・元へ戻る。64小節で同じ流れへ戻る |

モードを変えると演奏は停止し、次のPlayで冒頭から始まる。再生モード以外に未保存の編集がある場合は切替前に確認する。モードだけの切替では確認を出さない。Stop後に勝手に再開せず、ページを開くだけでも音は出ない。選んだモードはコード内に残り、名前付き下書きへ保存できる。

native sine kick／white hat／triangle bassの3パートで、追加の303・録音音源・外部AIは使わない。この作品の曲内masterの既定は60%、固定ループと自動展開は60%を上限にする。作品の音量は画面のLEVELで0〜100%に調整でき、100%はこの作品の標準音量。既存の保存済みLEVELと下書きは保ち、他作品や共通engineの音量は変えない。各32小節の最後4小節でfadeし、冒頭2小節はキックだけ、ハットは2小節後、ベースは4小節後に入る。既存schedulerの一つのclockで反復し、繰返し用タイマーや周期的なコード再評価は増やさない。A/B・LIVE素材には使わない。

本人の聴感・音色採用・実iPhoneは未確認。選択・Play・保存の動作確認と、人間が聴いて選ぶ評価は別に扱う。

## どれが一緒に鳴る？

上の3つのボタンで演奏面を選ぶ。選択中の画面と、何が連動するかをその下に表示する。

| 画面 | 一緒に鳴るもの | 操作とコード |
|---|---|---|
| 試作・A/Bミックス | 選んだ1試作、またはAとBの試作をAのBPMで重ねる | A/Bの音量・クロスは表示中のコードと連動 |
| ライブセット | セットのドラム・303風の低音/返し・パッド・素材A/B | 打点・音符・MUTE・フェーダーをひとつのStrudelコードに保存 |
| 元の303×2＋909 | acidBrosの2台の303と11パートの909 | この楽器のステップとつまみ。Strudelの音符/音色とは別。切替時に前の演奏を停止 |

「2つの試作を組み合わせる」でA/Bを選び、**「組み合わせのコードを開く」→ Play**。さらに楽器を足したければ**「このA/Bでライブセットへ」**を押す。
開いている組み合わせなら、両方のコード・AのBPM・A/B音量・クロスを持ち込む。まだ開いていなければ、選んだ公開試作と端末に残るA/B設定から作る。
追加のドラム・303・パッドは全てMUTEで始める。ミキサーのMUTEを解除すると同じBPMで足せる。移動前が停止中なら音は始まらず、再生中なら組み合わせを引き継いで演奏を続ける。

引き継ぎ先の素材A/Bには通常セット用の小さい減衰を掛けず、元ミックスに近い音量を保つ（最終gainは0.7から0.66）。この固定gainはリミッターや自動音量補正ではない。素材にも低音があるため、全体音量と追加パートの音量で調整する。「保存」でA/Bのコードと全設定を名前付き下書きへ残す。
素材A/Bの中の音符・音色は表示コードの`setLayerA` / `setLayerB`内で編集する。セットの303フェーダーは追加の303風に効き、素材内の303へ自動で割り当て直す操作ではない。取り込んだセットは「追加の303風」「追加パート」と表示する。
コードのA/B各本文内の編集も持ち込めるが、外側の混合処理や構造まで編集したコードは推測して変換せず、移動ボタンを無効にする。整数の60〜180 BPMが対象。元の公開試作/下書きは上書きしない。
普通のセットを選ぶ操作はそのプリセットを開くため、現在のA/Bは自動で引き継がない。元のacidBrosの音をA/Bに取り込む機能、acidBrosからStrudelへの音符/音色変換・共通clockは未実装。

## テクノ・ライブセット（PC / スマホ）

最初はシンプル表示。**再生 → 少し変える → 保存**で遊び、楽器だけ替えたい時は「🎲 楽器だけ」。再生・全停止・全体音量・保存はスクロールしても上に残る。音色とパートの音量／MUTEを前に出し、細かい操作は「全操作を開く」で表示する。「コードを見る」も全操作を開いて同じコードへ移る。表示切替だけでは演奏やコードは変更しない。

- **楽器を選ぶ・固定する**：低音／返し／パッドの選択と固定。閉じても現在の固定内容と909／808風を表示する。MUTE中や自動展開で休んでいるパートは、楽器を替えても鳴らない。
- **ここを戻り先に → 戻り先へ戻す**：遊んで試し直すための目印。端末へ残すには上の「保存」を押して名前を付ける。
- **保存 → 保存版を開く**：既存の下書きとJSONバックアップ。保存フォームや結果・エラーは演奏面で見える。表示切替でも入力途中の名前とフォームを保つ。
- **全操作を開く**：16ステップ、音符、素材A/B、手動シーン、展開間隔と盛り上がり、コード。シンプルに戻しても設定はそのまま。必要な時だけ詳しく触る。

以下の打点編集・素材A/B・詳しい展開操作は「全操作を開く」から。

入口: <https://music-private-live-workbench.pages.dev/?stage=techno>。PC幅でrootを開いた時もこの演奏面から始める。既存の試作URLはその試作を開き、上の「ライブセット」で切り替えられる。同じアプリ・同じ公開先で、新しいサイトやrepoは増やさない。

|---|---|
| Acid Drive | 128 BPM、909＋歪んだ303風ベース |
| Dub Room | 122 BPM、音数と歪みを減らした低い303 |

1. 上の「ライブセット」からセットを選び「再生」。新セットはLIVE自動展開がオン。PCでは音色とミキサーが並ぶ。全操作ではドラム・音符・素材A/Bも表示する。スマホは縦に並び、全操作のドラム行は横スクロールできる。最初の再生は手動。
2. ドラムの16打点をクリック。303の16音符はクリックで次の音、Shift＋クリックで休符。全パートと素材A/Bは**一つのStrudel clock**で鳴る。
3. INTROはキックと閉ハット、GROOVEでスネアと開ハット、ACIDで303の低音と高い返し・カウベルを足す。BREAKはドラム欄のキック・スネア・開ハットを抜く。新セットのPEAKはハットを常時倍にせず、8小節目だけ静かな1打を足す。手で置いた打点・音符・MUTEは残る。
4. LIVEは8/16/32小節ごとに展開し、8つの展開で一章。次の章では展開順と弱拍の変奏候補が変わり、同じ64小節だけを繰り返さない。AIモデルの生成ではなく、保存コードの規則。「盛り上がり」で返し・打楽器・明るさを調整し、「今の展開をキープ」で流れを留める。手動シーンを押すとLIVEと展開キープを解除する。旧V1/V2のAUTOは元の64小節を維持。
5. フェーダーは停止中にも調整でき、演奏中は再評価なしで次の音から反映する。明るさはフィルターの開き、みょんは共鳴、歪みは硬さ、うねりの長さはフィルターの余韻。808の低音の長さは808風キックだけに効く。BPMは全パート共通。打点・音符・音色・シーンの変更は短くまとめて次の演奏処理から反映し、厳密な小節頭予約ではない。
6. 素材A/Bは既存8試作から選び、音量を少しずつ上げる。コードを現在のBPMに合わせて再生し、音量0の発音は除外する。素材にもドラムや低音があるため重ねる時は小さめに。クロスは左=A、右=B、中央=両方。
7. 「保存」で名前付き下書きに、打点・音符・音色・BPM・全フェーダー・MUTE・素材のコード・AUTOと変奏seed/固定/採用前の軸、LIVEの流れ・間隔・盛り上がり・キープを残す。「保存版を開く」→下書き一覧で復元。JSON持ち運びにも同じ保存コードが入る。再開は1小節目から。別のプリセットを選ぶ時は未保存編集を確認する。

PCはSpaceで開始/停止、1〜5でシーン、Escで全停止。入力欄・コード編集中はSpaceと数字を奪わない。停止後の再開は1小節目から。初回は音声処理の準備を待ってから開始し、準備待ち/打点変更直後のStopでも勝手に再開しない。

808風はサイン波の低音とpitch envelope、ノイズのスネア/ハット、金属的な合成カウベルによる**近似**。Roland純正のエミュレーションではない。追加音声ファイル・外部808バンク・有料pluginは不要。既存のオフライン音7本でセットと素材を使える。別画面のacidBrosは従来どおり独立した時計で、同時同期しない。

コード本文を直接編集した版でも、`const SET_MASTER = slider(...)`など接続が一つ残るフェーダーは使える。演奏中の全体音量・音色は数値だけ変え、本文やコメントを保つ。コードの変更は「コードを反映」。打点・展開・MUTEなど本文を生成し直す操作は無効になるため、戻す時はUndoか、先に保存してプリセットを選び直す。接続を削除・重複したフェーダーだけは無効になる。実PCの好み・出力音量、実iPhoneの操作/出音は本人確認。

演奏画面の上の「アプリ更新」で新しい版を確認して開き直せる。更新待ちがあれば「更新あり · 開き直す」と表示する。「ホーム画面・オフライン」にも同じ更新/再読込がある。再生中や未保存編集は先に確認し、保存済みの下書き・FILEは保つ。別タブが更新済みでも、この画面を再読込できる。旧版で上のボタンがない場合は下の「ホーム画面・オフライン」→「アプリを更新・再読込」。Ambient Driftがなければこの更新を試す。

人間とAIの協奏では、人間がフェーダー・打点・シーンを触り、AIが同じコードのフレーズや展開を編集する。現在は一つの画面とコードを共有する方式。AIのコード本文変更がセット形式を外れた場合は手動コードとして保存し、操作面へ戻すにはUndoか明示的なプリセット選択を使う。別ウィンドウ間の状態同期、チャット指示の自動受信、小節頭でのAI変更予約は未実装。

### 軸を守って変化させる（2026-10-01）

新しく開く4セットは`TECHNO_SET_V4`。保存済みV3は明示更新まで維持する。軸の16ステップを4小節反復し、次の4小節は弱拍の1音または2音だけを隣の音へ動かす。休符と4つの強拍は変えず、8小節で軸へ戻る。章と16小節区間から次の候補を決め、軸へ変更を累積しない。同じseed/設定は同じ展開を再現する。Dub Roomの初期フレーズは強拍だけなので、音符の変奏は起こらず、音色とパートの抜き差しで変わる。

- 「音符を固定」は軸の音符を反復する。音色・アクセント・パート展開は続く。音色も固定するには「音色の起伏」を0にする。
- 「別の小変奏」はseedを進めて候補を変える。演奏中の表示が「小変奏 · 5〜8小節」の時、「今の変奏を残す」でそのフレーズを新しい軸にして固定できる。「採用前へ戻す」は一つ前の軸へ戻す。
- 303は低音の鋸歯波と高い矩形波の返しを同じclockで混ぜる。返しは低音に対する短3度/5度を共有スケールに絞り、数ステップだけ鳴らす。「303返し音量」とMUTEで出し入れする。左右固定ではない。
- 「303の2役・残響・音色の起伏」を開く。残響はテンポ同期の短いディレイ、音色は展開間の補間と展開間隔の2倍の呼吸で変わる。明るさ/起伏はパッドにも効く。スライド風は各音のpitch envelopeによる近似で、元303の発振器を継続するレガートとは違う。
- 「追加打楽器を出す」でCLAP / RIM / LOW・MID・HIGH TOM / CRASH / RIDEを選ぶと打点行が現れる。LIVEのタムは盛り上がりが標準以上の8小節目だけ、ブレイクでは抜く。クラッシュはブレイク後/山場の入口。音量/MUTEは一括。5音は合成、2シンバルは同梱済みacidBrosのWAVを再利用し、新しい音声は不要。

### やわらかく長めに聴く

[Ambient Driftを開く](https://music-private-live-workbench.pages.dev/?stage=ambient) →「再生」→「聴くだけ」。76 BPM・32小節間隔で、長い三和音とフィルター/音量がゆっくり移る。「流れ」のアンビエントは自動ドラム/303を抜く。パッド音量とMUTEで背景の和音を調整でき、素材A/Bは手動音量が残るため、ドラム入り素材を足せばそのドラムは鳴る。

新しい音源・モデル・音声ファイルは増やさず、既存のStrudel合成を使う。自動展開はStrudelの音声時計に対する純粋関数で、定期的なコード書換えや再評価はしない。UIの章/展開表示も同じ規則と時計を使う。「聴くだけ」は表示を畳むだけで、別プレーヤーや録音ファイルにはならない。スマホの画面ロック/他アプリ/車載出力での継続再生は端末依存で未確認。現状は開いたブラウザでの連続LIVEで、長時間の背景再生を保証しない。

### ランダムで弾く（LIVEセット）

「ライブセット」→「再生」の下にある **🎲 フレーズ** で、低音の短い反復と終わりの返し、ハットの打点、楽器、音色をまとめて変える。低音と返しは共通のC minor。7〜10音のフレーズ、4つの裏拍ハット＋最大2つの返しで、連打しても音数を積み上げない。キック・スネアの打点、BPM、各音量、MUTE、素材A/B、追加打楽器の選択とLIVEの時計は保つ。

- **🎲 楽器だけ**：音符・全打点・ツマミ値を保ち、低音・返し・パッドを各3候補から今と違う楽器にする。ドラムは既存の909／808風合成を交互に切り替える。パートを追加したりMUTEを解除したりはしない。
- **少し変える**：今の休符と強拍を保ち、弱拍の最大2音を隣の高さへ動かす。ハットの返しと音色も小さく変え、楽器は1役だけ替える。ドラム音源は保つ。
- **音符を固定／ドラム固定／音色ツマミ固定／楽器固定**：独立した固定。ドラム固定は打点と909／808風の両方、楽器固定は3役とドラム音源、ツマミ固定は6音色値を保つ。楽器固定中も選択欄の手動変更はできる。アンビエントはパッドの楽器と音色だけ変え、ドラムや低音を増やさない。
- **ここを戻り先に**：今の16音・装飾ドラム・6音色値・楽器・ドラム音源を戻り先にする。鳴っている自動小変奏を16音の軸へ採用する時は従来の「今の変奏を残す」を使う。
- **戻り先へ戻す**：最初のサイコロ前、または最後に「ここを戻り先に」を押した状態へ戻す。後から手で変えた音量・BPM・MUTEは巻き戻さない。
- **保存**：候補の音符・打点・音色・楽器・ドラム音源、乱数seedと試行番号、固定設定と戻り先を既存の下書き／JSONに残す。

楽器は同じ欄の選択メニューで手動でも替えられる。低音は303風ノコギリ／ゴムっぽい矩形／FMベース、返しは矩形／ガラス風FMプラック／丸い三角波、パッドは暖かい三角波／柔らかい正弦波／空洞っぽいFM。実機・生楽器の録音ではなく、既存Strudelの合成音。音符・アクセント・スライド風・エンベロープと共通の音色フェーダーを使い、別パートを重ねない。候補別の固定gainで強い音を控えめにするが、聴感の自動音量補正ではない。追加音源・依存・ダウンロードはなく、PWAの同じ配布物へ含む。

音程・スライド風・アクセント・返しの実装は既存のLIVE合成器を使う。元のacidBrosのサイコロは別の操作として残す。サイコロは押した時だけコードを書き換え、演奏中は既存の100msまとめ反映を使う。毎小節の再生成、新しい音声時計、音声・外部AI・依存追加はない。保存済みV1〜V4はボタンを押すまで従来コードのまま。コード本文を直接編集した版は自動書換を止める。

### 元のacidBrosサイコロとAUTOの差

比較元は同梱v153の[Data.js](third_party/acidbros/js/data/Data.js)、[TB303.js](third_party/acidbros/js/audio/TB303.js)、[AudioEngine.js](third_party/acidbros/js/audio/AudioEngine.js)。全体のサイコロは次の関係をまとめて作る。

| 要素 | 元の全体サイコロ | 旧セットAUTO → 新セット |
|---|---|---|
| 2台の303 | 2号を低音、1号を上のフレーズにし、共有スケールと音程関係で組む | 1本の同じ16音 → 低音と疎な返し、4小節反復＋小変奏 |
| リズム | 低音は強拍優先、弱拍に同音反復。909は四つ打ちと裏拍に少量のフィル | パート出し入れとハット倍化 → 骨格を保持、フィルは8小節目だけ |
| アクセント/スライド | 発音に紐づけて生成、スライドは同じ発振器を続ける | 毎音ほぼ同じ → 強拍アクセントとpitch envelope近似 |
| 音色/空間 | 各303の波形・cutoff・共鳴・包絡・delayが独立 | 固定値 → 手動フェーダー＋ゆっくりしたcutoffの起伏・tempo delay |
| 気に入った版 | 303/909単位のLOCKとFILE保存 | 既存保存 → 音符固定、変奏採用/一段戻し、seed保存 |

2台は独立したTB303インスタンスで、同じ時計から共通のmaster compressorへ混ざる。LRに振り分ける処理はない。909の11パートはbd / sd / 3 toms / rim / clap / closed・open hat / crash / ride。元画面のMANAGE TRACKSで出し入れ、7種の合成音は歯車から編集し、自分のサンプル割り当てもできる。今回のStrudel版は役割を取り入れた近似で、元の全体サイコロや音色編集器をそのまま移植したものではない。

## 従来の試作・コードを使う

1. スマホまたはPCで入口を開く。PCのセット画面からは上の「試作・A/Bミックス」で一覧へ。スマホのrootは `aphex1`。`Acid 303 / 909` のハード版と初稿、`Techno 01・直進`、`Techno 02・余白`、`Auto Groove・毎周変化`、前の高速版と従来の4小節テストも一覧から選べる。
2. 最初に `Play` を押す。再生中に別の試作を選ぶと、コードを読み込んで演奏を切り替える。Afterimage Synth v1は選択時に止め、Playで冒頭から開始する。iPhoneでは最初の音声再生にタップが必要。停止中に選んでも音は勝手に鳴らない。
3. コードを変更したら `コードを反映` を押す。`Stop` ですぐ停止する。`選択中の版に戻す` で元コードへ戻る。
4. 気に入った編集は `この端末に保存` を押し、画面内の名前欄で下書きとして保存する。同じブラウザの下書き一覧からコードを戻せる。未保存のまま切り替える時は画面内で確認できる。読込待ちの間にさらに編集した場合も、置き換える前にもう一度確認する。キャンセルすると現在のコードと選択、演奏を保つ。
5. `Acid 303 / 909` を選ぶとコードの上に4本の縦フェーダーが出る。停止中もCUTOFF（明るさ）、RESONANCE（みょん感）、DRIVE（歪み）、DECAY（うねりの長さ）を調整でき、Playでその値から開始する。演奏中の数値はその場でコードにも残り、次の発音から反映される。元に戻すなら初稿を選ぶか「選択中の版に戻す」を押す。
6. コードの上の「この試作の音量」で、公開試作ごとに0〜100%の音量を合わせる。100%は元の音量、0は消音。Play中も動き、値はコードと**この端末のブラウザ**に試作ID別で残る。音を自動採点・均一化する機能ではなく、耳で合わせる。
7. ページ先頭の「2つの試作を組み合わせる」で公開試作をA/Bに選び、「組み合わせを開く」→Play。A/B音量と横のCROSSFADEを動かす。左端はAだけ、中央は両方、右端はBだけ。BはAのテンポに同期するので、違うBPMの2曲を元の速さのまま独立再生するDJデッキではない。気に入った組み合わせは「この端末に保存」でコードごと下書きへ残せる。`?deck=acid-303-909,techno-dub`のようなURLは公開試作の組み合わせを開くが、端末内の音量値は共有しない。
8. 単独モードでは上の「元の303×2＋909」、または「演奏面のつながり」→「切り替えて開く」で、`acidBros`の2台の303と11パートの909を同じページ内で開く。スマホなら「全画面で開く」が操作しやすい。Strudelの演奏は止まる。中の`RUN`で再生し、16ステップの打点と各つまみを触る。`FILE`で保存してから「閉じて停止」。直行URLは`/?module=acidbros`。StrudelのPlayやライブセット操作面へ戻るとacidBrosを閉じて停止する。
9. 303＋909で`FILE → SAVE`すると、試奏台の「この端末の303＋909パッチ」に名前と更新時刻が出る。名前は中のFILEで変更できる。パッチ名を押すとページ内に読み込み、隣の「全画面 ↗」ならスマホ向けの全画面でそのパッチを開く。読み込み前に現在の303＋909を停止する。未保存の調整がある場合は先にFILEで保存する。
10. 303＋909をページ内で開いた後、「StrudelのBPM → 303＋909」で現在選択中のコードのBPMを機械へ渡せる。逆の「303＋909のBPM → コード」は機械を閉じてStrudelコードの`setcpm`行だけを更新する。Playで聴き直し、残すなら「この端末に保存」。どちらもボタンを押した時だけの転送で、再生位置や音を同期しない。`setcpm`行が一つに定まらないコードでは転送ボタンを使えない。
11. 別の端末で続きを触るなら、試作一覧の下の「持ち運び・バックアップ」を開く。「保存済みをJSONに書き出す」でファイルを保存し、別の端末へ転送する。そちらの同じ欄でファイルを選び、名前・件数を確認して「この端末の一覧に追加する」。コードは下書き一覧、303＋909はパッチ一覧から選び直せる。公開ページとPCローカルの間でも同じ手順。

### 端末間で持ち運ぶもの

先にStrudelは「この端末に保存」、303＋909は中の`FILE → SAVE`。バックアップには**保存済みのコード下書き、作品別LEVEL、2デッキ設定、acidBrosのFILE**が入る。未保存のコードや303のつまみ・打点、演奏位置、音声ファイルは入らない。独自の音源を参照するコード・FILEでは、転送先にもその音源が必要。ファイルを自分で保存・転送する方式で、サーバーへアップロードしたり自動同期したりはしない。

読み込みは今ある保存版と設定を保って追加する。同じ保存版の再読込は件数を増やさず、異なる内容でIDが重なれば別IDにして両方を残す。既に設定のある作品・デッキには現在の端末の値を使い、未登録の設定だけ追加する。取り込んだ設定を使うには作品・組み合わせを開き直す。再生中のコードや303＋909の現在選択は追加操作では変更しない。

取り込んだ下書きは選択時にStrudelを止めてコードを開く。確認後にPlayまたは「コードを反映」で演奏する。JSONを選ぶ・一覧に追加するだけではコードを実行しない。303＋909も一覧から選び、RUNを押す。読み込み前にJSONの形式・件数・数値・FILEコンテナを確認し、容量不足などで保存が失敗した場合は先に書いたキーを戻す。

本人用の作品はこの下書き棚で選べる。読み込みは公開作品一覧やサーバーへ送らず、コード内の音量もそのまま保持する。Strudelの音符列・打点列をmini記法で書く場合は、`s("bd ~ sd ~")`のように二重引用符を使う。単一引用符の列は通常の文字列として扱われるため、JavaScriptの構文が通るだけでは演奏の一致を確認できない。

acidBros内の`FILE → EXPORT ALL`のJSONもここで読み込める。古いFILE形式で読めない場合は、303＋909のFILEで開いて保存し直してから書き出す。バックアップは8 MB以内、コードとFILEはそれぞれ500件まで。ブラウザの空き容量が足りなければ追加できない。実iPhoneのファイル保存・受け渡し操作は本人確認待ち。

### 音を変える・公開試作

フェーダーを上げるほど数字が大きくなる。CUTOFF（初期420 Hz、範囲120〜2200 Hz）は高いほど明るく鋭く、低いほどこもる。RESONANCE（初期18、1〜35）は高いほど「ミョン」という共鳴が鋭く、低いほど丸い。DRIVE（初期3.2、0〜7）は高いほど歪んでザラつき、低いほど澄む。DECAY（初期0.18秒、0.03〜0.5秒）は高いほどフィルターのうねりが長く、低いほど短く切れる。DECAYは音符自体の長さを変えない。まず1本だけ動かし、Stop後に「選択中の版に戻す」で基準値へ戻すと差が分かりやすい。

公開試作9件は従来8作品＋Afterimage Synth v1。Gitの `src/library.json` と配信対象の `src/patterns/*.txt` で版管理する。原録音版Afterimage FINAL v1のソースは保管し、公開ビルドには含めない。作品の日付ではなく、この試奏台へ登録した日付を一覧に表示する。`Techno 01` は124 BPM相当の4つ打ち、`Techno 02` は112 BPM相当で音数を減らす。`Auto Groove` は116 BPM相当で高音パートを確率的に間引き、8小節ごとにキックを一度抜く。これはStrudelのパターンによる自動変奏で、AIが音を聴いて生成しているわけではない。音の好みは本人試聴で判断する。

2デッキはStrudelの単一clockで2つのパターンを`xfade`し、作品内の各パートのgainを保ったまま作品全体のgainを掛ける。中央で両方が鳴るため合成後に0.7倍のheadroomを設けた。大きさの最終判定と実iPhoneでの同時再生負荷は未確認。旧形式の標準下書きには音量フェーダーを追加して開き、独自構造のコードは変更せずに開く。

`Acid 303 / 909` は128 BPM相当。ドラムはStrudel標準の `RolandTR909` バンクを参照し、未保存時は外部から読み込む。PWAで音を保存した後とPCローカル版では、キック・スネア・閉/開ハットの先頭サンプル4本を端末から読む。303風ベースは鋸歯波・共鳴ラダーフィルター・フィルターエンベロープ・歪みでブラウザ内合成する。初稿より共鳴、フィルターのうねり、歪みを強め、歪みの後で音量を抑える。このStrudel版で参照する909バンクはrepoへ複製しない。画面の縦フェーダーはStrudelのコード内スライダーを操作するので、変更値はコードに残り再評価なしで次の発音へ反映される。コード中の青いスライダーからも操作できる。初稿は別IDで残し、一覧で選べば元のコードに戻る。気に入った状態は「この端末に保存」で名前を付け、公開版へ採用する時はGitの試作コードとListenの入口を同じ変更で更新する。

## 303＋909ブラウザモジュール

`acidBros` v153を独立した画面として同梱した。2台の303は発振器→フィルター→ディレイをつまみで変え、909は11パートの16ステップと音色パラメータを触れる。これは**モジュラー風の制作入口**で、自由なケーブル配線やVST読み込みはまだない。Strudelとは別の音源・保存形式。単独モードでは時計も別で、明示操作でBPMを双方向に転送し、切替時に前の演奏を止める。「一緒に鳴らす」では共通のAudioContextとStrudelの時計で同期演奏し、音量はそれぞれ調整する。組み合わせの名前付き保存に対応。パターンのコードへの自動変換、共通マスター処理はまだない。

同梱した909用WAVはハイハット・オープンハット・クラッシュ・ライドの4本、計438,798バイト。残りのドラムと303はブラウザ合成。外部サイトからこれらのWAVを毎回取得する必要はないが、初回は同じPages URLから読み込む。容量を小さくしたことが音声処理負荷やiPhoneのバックグラウンド再生を保証するわけではない。演奏中の各つまみの即時反映と端末上の保存を確認する。

`acidBros`の`FILE`保存は、その端末・そのブラウザの`localStorage`へ残り、Strudelの「この端末に保存」とは別。元のacidBrosサイトとの保存データも別。試奏台の保存一覧はこのacidBrosのFILEを参照する。別の端末には「持ち運び・バックアップ」のJSONを渡せる。`/modules/acidbros/?file=<ID>`はそのブラウザに既にあるFILEを選ぶ全画面URLで、他端末へパッチを渡す共有URLではない。単一パターンの共有にはacidBros内の`SHARE URL`も使える。公開版に採用するには、人の試聴後にこのrepoで更新する。上流版は自動更新されず、現在の出所・変更点・ライセンスは[`third_party/acidbros/UPSTREAM.md`](third_party/acidbros/UPSTREAM.md)を参照する。

## 人とComputer Useで一緒に触る

1. 人が音を聴きながらPlay、縦フェーダー、試作切り替えを操作する。同じブラウザ画面へComputer Useが接続できる場合は、AIもその画面の操作を手伝える。Stopは画面ですぐ押せる。
2. 「低音を短く」「909を少し薄く」など、聴感の要望をチャットで伝える。つまみだけで足りる変更は演奏中に操作し、ノート列・構成・音色の変更はコードを書き換えて「コードを反映」で試聴する。
3. 良い状態は「この端末に保存」で名前付き下書きにする。公開版に採用するコードと説明を選んだ後、Music repoの `src/patterns/`、`src/library.json`、Listen索引をまとめて更新し、チェックとデプロイを行う。

Computer Useの画面操作はその接続先の1ブラウザに限られ、スマホとPCの操作・音声・下書きは同期しない。チャットでのコード変更とGit/Pages更新には時間がかかるため、演奏中の即時操作はブラウザ内で行う。本人の聴感をAIが自動取得・採点する機能もない。

再生中の試作切り替えと、編集後の `コードを反映` はブラウザ内で演奏を更新する。GPT Liveとの直接接続、マイク・EP-133連動はまだ実装していない。

ブラウザ内で直したコードは自動で公開版へ同期しない。端末内下書きは `localStorage` に残り、別のスマホ・PCにはJSONバックアップで手動転送する。ブラウザの保存データを消すと下書きも消えるため、残す版はファイルにも書き出す。公開閲覧者にサーバーへの書き込み機能はない。

Afterimage（残像）/ Acid Drive Synth v1は既存の単曲棚から選べる合成別版。初回のJSON読み込みは不要。選択すると演奏を止めてコードを開き、明示Playで冒頭から開始する。128 BPM・256小節（8分）・seed731と全打点・構成を保ち、内蔵全体音量15%に外側の保存済み音量を掛ける。A/B・LIVE素材からは除く。保存した下書きも冒頭開始の指定をコード内に残す。

受領したFINAL v1スコアのAGPL-3.0-or-later（[LICENSE](LICENSE)）許諾に基づく派生版で、キックをsine、スネア・閉/開ハット・クラッシュをwhite noise、ライドをsquareとFMで合成する。6役のフィルター・包絡を分け、既存の各パートgainは保持する。録音参照・`samples(...)`・bank・外部音源URLは0。元の録音音色や音量感の再現は主張しない。原録音版 `src/patterns/afterimage-final-v1.txt` は7797 bytes・SHA256 `d59bb636b012d5e9d780b1127e54a6ae6b3310fd518ef49edc1e44b39289beb4` のままソースと履歴に保管し、公開棚とビルドから除外する。音源バイナリは追加しない。

初期REPLはscopeと合成音を準備し、旧作品用のdefault録音registryは最初の明示Play時に元URLのまま準備する。`// WORKBENCH_SYNTH_ONLY_V1` を持つSynth v1は、そのregistryと3ループ用の`samples(...)`前置きを省く。新しい取得先やcache対象は追加しない。実エンジンの短区間測定（0–8、120–128、248–256小節、44.1 kHz stereo）では非有限値・クリップ・録音音源GETは0、終端の余韻は減衰した。全8分の実音測定は未完了で、本人の試聴・音色採用・実iPhoneは未確認。第三者録音の公開・商用音声リリース権利は未解決で、スコアのAGPL許諾と音源の利用条件を同一視しない。先行Afterimage Synth v1は2026-10-05にmain e16dd967へmergeし既存Workbenchへ公開済み。棚分類・Minimal Techno 01追加の最終HEADと公開結果は対応PRの証跡で確認する。

`src/patterns/*.txt` にはStrudelの演奏コードを書く。既存3本の音声を使う時は `s("pad")`、`s("sub")`、`s("drums")` を指定でき、ページが公開音声URLの `samples(...)` 定義を先頭に足す。合成専用marker付きコードではこの前置きを省く。合成音やStrudel標準バンクは別に指定できる。公開試作は一覧から選ぶとコードが戻り、更新は同じIDの内容を直すか、新IDを追加して旧版を残す。KVに新しいパートを増やす場合はAPIの許可名と音声ファイルを一緒に更新する。

既存の `GET /api/pattern` の互換用KVコードを管理者が更新する例（通常の試作一覧には反映されない）：

```powershell
npx wrangler@4.129.1 kv key put '<LIVE_PATTERN_KEY>' --path '<pattern-file>' --namespace-id '<KV_NAMESPACE_ID>' --remote
```

## スマホのホーム画面・オフライン

### ライブ中のフェーダー・BPM・スマホ音量

- 手動フェーダーは基準値。LIVE中はその下の小バーに、同じ演奏時計で計算した「展開後」の値を表示する。自動の抜き差しと明るさが見え、基準値を触ると追従する。小バーは音声を測るVUではなく、全体音量・音色・各発音の強弱より前の制御値。停止中・聴くだけ・本文を手直しして生成形式が変わった版では表示しない。
- BPMは数字または横フェーダーで60〜180を操作する。演奏時計へ直接渡し、コードのmetadataと`setcpm`だけを書き換える。全コードの再実行や音源再取得はせず、既存フェーダーの接続・軸の音符・旧V1/V2/V3保存形式を保つ。「再生 ○ BPM」は実際の時計の値。打点／シーン変更は従来どおり必要なコード反映が入る。
- 保存するとBPMと手動基準値・自動展開の設定を残す。自動値を毎フレームcodeへ書く処理はない。表示は既存の80ms更新を使い、非表示のページと「聴くだけ」では小バーを更新しない。実iPhoneの長時間負荷は未測定。BPMの自動加速は既定に追加しない。
- 上部の「音が出ない・端末の音量ボタンが効かない時」に、Strudel用の「音を再接続」を置く。初回のworklet初期化は一度だけ、再開時には既存AudioContextを毎回resumeする。ページへ戻った時の復帰も既に再生中の時だけで、停止した演奏を勝手に始めない。対応ブラウザでは`navigator.audioSession.type = 'playback'`を音楽再生時に指定し、未対応では通常のWeb Audioを使う。
- ページの音量、スマホのメディア音量、車の音量は別。出力先と物理ボタンの音量はOSと接続先が決めるため、ページから強制変更できない。iPhoneのコントロールセンターで再生先を選んだ後、無音なら再接続。復帰しなければ編集保存→アプリ再読込。acidBrosは別エンジンなので中のRUNを押し直す。実iPhone／Bluetooth／CarPlayでの物理音量ボタンと再接続は本人確認待ち。

根拠: [MDN Audio Session API](https://developer.mozilla.org/en-US/docs/Web/API/Audio_Session_API)、[AudioContextの中断と復帰](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state)、[Appleの出力先選択](https://support.apple.com/en-gb/guide/iphone/iph315e0d58d/ios)。API指定は端末の出力先を強制するものではなく、実機の問題が解消したとはまだ主張しない。

### ホーム画面へ追加・音を保存

1. [試奏台](https://music-private-live-workbench.pages.dev/)をiPhoneのSafariで開く。共有メニュー →「ホーム画面に追加」→「追加」。「Webアプリとして開く」があればオン。[Appleの手順](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)。AndroidはChromeのメニューから「アプリをインストール」または「ホーム画面に追加」。対応ブラウザでは画面内の追加ボタンも使える。
2. ホーム画面のアイコンから開く。「ホーム画面・オフライン」を開き、ネット接続中に「オフライン用の音を端末に保存」。**「オフライン準備OK」になるまで待つ**。
3. 機内モードなどで同じアイコンから開き直し、作品を選ぶ → Play。303＋909は「この中で開く」または「全画面で開く」→ RUN。自動では再生しない。
4. 編集は従来の端末内下書き/FILEへ保存。「更新あり」が出たら編集を保存して「アプリを更新・再読込」。更新を検出しただけで演奏を止めたり画面を開き直したりはしない。

アプリ本体/acidBrosの約6.7 MBと、公開3ループ＋固定909の4音の約3.2 MBを、このブラウザのCache Storageへ保存する。全7音の保存が成功してから新しい音源セットへ切り替え、失敗時は前の完全セットを残す。音を更新したい時はネット接続中に「保存した音を更新する」。Strudel版909の4音は外部の固定commit・SHA-256を検証し、**その端末だけに直接取得する**。MusicのGit/Cloudflare配布には追加しない。

ブラウザとホーム画面アプリで保存領域が別になる場合があるため、追加したアプリで準備する。下書き/FILEが見えなければ元ブラウザのJSONバックアップを持ち込む。サイトデータの削除やOSによる保存領域の整理で音が消えた時はネット接続中に再保存。PWAの保存は永続保存の保証ではない。大事なコード/FILEはJSONにも残す。PC/別端末への自動同期や画面ロック中の演奏保証はない。実iPhoneのホーム画面追加・機内モードの出音・長時間の保存維持は本人確認待ち。

### 音源の所在と追加方法

| 音 | どこから読むか | オフライン |
|---|---|---|
| Strudelの合成音・303、acidBrosの303と一部ドラム | ブラウザ内で合成 | アプリ本体の保存だけで使える |
| pad / sub / drums | 自分のCloudflare KV公開APIの3ループ | 音保存ボタンで端末へ取得 |
| Strudel標準909のキック/スネア/閉/開ハット | 外部の標準バンク | 固定版4音を音保存ボタンで端末へ取得 |
| acidBrosのハット/シンバル4本 | アプリ同梱のWAV | アプリ本体と一緒に保存 |
| コードに新しく指定した外部URLや他の標準バンク | その参照先から再生時に取得 | 自動では保存しない。ネット接続が必要 |

コードを保存しても、その中の音声ファイル自体は入らない。追加音源をオフラインに含めたい時は、対象URL・利用条件・容量・hashを確認して、必要な音だけ保存対象へ追加する。自前のループを公開する場合は管理者がKVとAPIの許可名を更新する。現画面には任意の音声アップロード機能はない。端末への保存は通信待ちを減らすが、音数・エフェクト・端末性能による処理負荷は別。

PWAのSWはこの独立Pages originだけに登録し、MusicのFM / Band Room / Core Rigとは別。build時に全静的ファイルのhashを生成し、混ざった配信世代をcacheしない。Pagesの`/index.html → /`転送はhash確認後のdecoded bodyからResponseを作り直し、転送flagと圧縮metadataを持たずに保存する。公開音源7本だけを明示保存し、private APIや未登録の外部URLはcacheしない。Safari等のWAV Rangeリクエストに206で返す。SW更新は下書き/FILEのlocalStorageを変更しない。

## PCでローカル起動・オフライン試奏

これはネイティブアプリではなく、**PC上のローカルHTTPサーバー＋Chrome/Edgeなどのブラウザ**で使う。同じ `Music` repo と同じ画面・公開試作の棚を使い、新しいrepoや常時接続のオンラインブラウザは要らない。`index.html`を`file://`で直接開く方法では、モジュールと音声APIの経路が成立しない。

初回だけネット接続中に、`experiments/workbench/v1` で次を実行する。

```powershell
cd C:\workspace\music-stack\Music\experiments\workbench\v1
npm ci
npm run local:prepare
```

これで固定版Strudelを含む画面をビルドし、公開中の3本のループとStrudel版アシッドで使う909の4音（計約3.2 MB）を `C:\Users\<ユーザー名>\.music-live-workbench\sounds` に保存する。909の4音はcommitを固定した公開標準バンクからその端末だけに取得し、Gitには追加しない。元サンプルrepoの再配布ライセンスは未確認のため、この機能では配布しない。保存後の起動と従来8試作の切り替えにはネット接続不要。Afterimage Synth v1／Minimal Techno 01の音には録音音源は不要だが、正式ローカルサーバーの既存準備・起動条件は維持する。既存曲の端末内909登録は変更しない。

```powershell
npm run local
```

起動メッセージの `http://127.0.0.1:8788/` をPCのChrome/Edgeで開く。サーバーはPC自身からだけ開ける。終了は起動したターミナルで `Ctrl+C`。公開ページの音源や固定Strudel版を更新したい時だけ、ネット接続中に `npm run local:prepare` を再実行する。任意のポートは `MUSIC_WORKBENCH_PORT`、音源保存先は `MUSIC_WORKBENCH_SOUND_DIR` で変更できる。

ローカル版は旧作品の最初の明示Play時に標準音源一覧を端末内の小さな一覧へ差し替える。合成専用の両単曲ではこの録音準備を行わない。従来8試作に必要な3ループと909の4音は使えるが、**新しく書いたコードが他のStrudel標準サンプルや外部URLを参照する場合はオフラインでは鳴らない**。別のサンプルを使うにはオンライン公開版で試すか、必要な音を明示的に準備する。acidBrosの4 WAVは従来どおり画面と一緒にビルドされる。PCローカルとCloudflare公開URLは別originなので、ブラウザの下書き・音量・acidBrosのFILE保存は自動で共有されない。「持ち運び・バックアップ」のJSONで手動転送できる。スマホでは従来の公開URLを使い、PCの `127.0.0.1` には接続できない。

### OSS活用・更新と軽量化の方針（計画）

2026-10-01の本人方針は、既存OSSの音源を利用し、復元できる保管と更新の取り込み、より良い音源への部分的な差し替えを検討すること。音源の全面自作を既定工程にしない。自前部分は操作/コードの連動、作品の保存/索引、気持ちいい展開、軽量化を磨く。新しいrepoやページを既定の出口にしない。

StrudelとacidBrosは固定版を同じ配信へ同梱しており、上流サイトの停止だけで配信済みの版が止まる構成ではない。ただしGitだけでnpm依存とKV上の3ループを全復元できるわけではない。PWA cacheはOSによる削除もあるため永続バックアップとは扱わない。依存ソース/パッケージ・音源・ライセンスを復元可能な一式へ保管する整備は未完了。外部909音源の再配布条件は未確認で、repoへ追加しない。更新は試作・保存コードの互換性/出音を確認して取り込む。必要な音や挙動だけ独立実装する選択肢は残す。

無償公開は現在のAGPL版でも可能。「条件なし」への変更は別問題で、Strudelやその派生コードを単に改名・書き換えてMIT扱いにはしない。独立して作成した部分の公開条件は別途選べるが、MITの借用部分には著作権/ライセンス表示が必要。音源・フォント・画像もコードとは別に出所を確認する。現在のライセンス変更は行わない。

軽さは同時発音数の上限、残響/フィルター数の制限を軸に測る。「一緒に鳴らす」は時計とAudioContextを共有するが、両方の音源を動かす分の負荷は増える。現在はタブ非表示時の演奏面更新と、聴くだけで隠した打点の点滅更新を省き、表示中もステップが進んだ時だけ打点表示を変える。音の時計/パターン/自動展開は変えない。短いサンプル再生と合成音のどちらが軽いかは音源の実装次第。コード量やダウンロード容量だけで演奏中CPU負荷を判定しない。低負荷モードや同条件でのNamima比較、実iPhone測定はまだ未実装/未確認。
