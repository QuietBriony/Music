# 公開ブラウザ制作台（v1）

`Music` repo 内の独立したブラウザ試奏台。PCとスマホで同じCloudflare Pages URLを開き、3本のループやStrudelの合成音・標準ドラムバンクを聴きながらコードを変える。入口・配信・公開試作の索引は一つだが、演奏面は **Strudel と acidBros の別エンジン**。BPMと保存パッチを明示操作で受け渡し、切り替える時は前の演奏を止める。既存の `music-stack.pages.dev` とGitHub Pagesの公開再生は変更しない。

入口: <https://music-private-live-workbench.pages.dev>。既存Pagesプロジェクトの名前には `private` が残るが、**このページ、試作コード、3本のWAVは公開**される。URLを知る人は音源を取得できる。検索結果には載せない設定だが、これはアクセス制限ではない。

スマホはホーム画面に追加できる**PWA**。ネット接続中にアプリと必要な音を約10 MB保存すると、既存の8試作と303＋909をオフラインで使える。追加したアプリ側で「準備OK」を確認する。PCには従来のローカルHTTP起動もある。

## どれが一緒に鳴る？

上の3つのボタンで演奏面を選ぶ。選択中の画面と、何が連動するかをその下に表示する。

| 画面 | 一緒に鳴るもの | 操作とコード |
|---|---|---|
| 試作・A/Bミックス | 選んだ1試作、またはAとBの試作をAのBPMで重ねる | A/Bの音量・クロスは表示中のコードと連動 |
| ライブセット | セットのドラム・303風の低音/返し・パッド・素材A/B | 打点・音符・MUTE・フェーダーをひとつのStrudelコードに保存 |
| 元の303×2＋909 | acidBrosの2台の303と11パートの909 | この楽器のステップとつまみ。Strudelの音符/音色とは別。切替時に前の演奏を停止 |

「2つの試作を組み合わせる」でA/Bを選び、**「組み合わせのコードを開く」→ Play**。さらに楽器を足したければ**「このA/Bでライブセットへ」**を押す。
開いている組み合わせなら、両方のコード・AのBPM・A/B音量・クロスを持ち込む。まだ開いていなければ、選んだ公開試作と端末に残るA/B設定から作る。
追加のドラム・303・パッドは全てMUTEで始める。ミキサーのMUTEを解除すると同じBPMで足せる。移動前が停止中なら音は始まらず、再生中なら組み合わせを引き継いで演奏を続ける。

引き継ぎ先の素材A/Bには通常セット用の小さい減衰を掛けず、元ミックスに近い音量を保つ（最終gainは0.7から0.66）。全体音量と追加パートの音量で調整する。「セットを保存」でA/Bのコードと全設定を名前付き下書きへ残す。
素材A/Bの中の音符・音色は表示コードの`setLayerA` / `setLayerB`内で編集する。セットの303フェーダーは追加の303風に効き、素材内の303へ自動で割り当て直す操作ではない。取り込んだセットは「追加の303風」「追加パート」と表示する。
コードのA/B各本文内の編集も持ち込めるが、外側の混合処理や構造まで編集したコードは推測して変換せず、移動ボタンを無効にする。整数の60〜180 BPMが対象。元の公開試作/下書きは上書きしない。
普通のセットを選ぶ操作はそのプリセットを開くため、現在のA/Bは自動で引き継がない。元のacidBrosの音をA/Bに取り込む機能、acidBrosからStrudelへの音符/音色変換・共通clockは未実装。

## テクノ・ライブセット（PC / スマホ）

入口: <https://music-private-live-workbench.pages.dev/?stage=techno>。PC幅でrootを開いた時もこの演奏面から始める。既存の試作URLはその試作を開き、上の「テクノ・ライブセットを開く」で切り替えられる。同じアプリ・同じ公開先で、新しいサイトやrepoは増やさない。

| セット | テンポ・音 |
|---|---|
| Acid Drive | 128 BPM、909＋歪んだ303風ベース |
| Dub Room | 122 BPM、音数と歪みを減らした低い303 |
| Electro 808 | 134 BPM、変則キックと808風の合成音 |
| Ambient Drift | 76 BPM、長い三和音とゆっくり移る柔らかいパッド。自動ドラムなし |

1. 上の「ライブセット」からセットを選び「セットを鳴らす」。新セットはLIVE自動展開がオン。PCではドラム・303・ミキサー・素材A/Bが並ぶ。スマホは縦に並び、ドラムの行は横スクロールできる。最初の再生は手動。
2. ドラムの16打点をクリック。303の16音符はクリックで次の音、Shift＋クリックで休符。全パートと素材A/Bは**一つのStrudel clock**で鳴る。
3. INTROはキックと閉ハット、GROOVEでスネアと開ハット、ACIDで303の低音と高い返し・カウベルを足す。BREAKはドラム欄のキック・スネア・開ハットを抜く。新セットのPEAKはハットを常時倍にせず、8小節目だけ静かな1打を足す。手で置いた打点・音符・MUTEは残る。
4. LIVEは8/16/32小節ごとに展開し、8つの展開で一章。次の章では展開順と弱拍の変奏候補が変わり、同じ64小節だけを繰り返さない。AIモデルの生成ではなく、保存コードの規則。「盛り上がり」で返し・打楽器・明るさを調整し、「今の展開をキープ」で流れを留める。手動シーンを押すとLIVEと展開キープを解除する。旧V1/V2のAUTOは元の64小節を維持。
5. フェーダーは停止中にも調整でき、演奏中は再評価なしで次の音から反映する。明るさはフィルターの開き、みょんは共鳴、歪みは硬さ、うねりの長さはフィルターの余韻。808の低音の長さは808風キックだけに効く。BPMは全パート共通。打点・音符・音色・シーンの変更は短くまとめて次の演奏処理から反映し、厳密な小節頭予約ではない。
6. 素材A/Bは既存8試作から選び、音量を少しずつ上げる。コードを現在のBPMに合わせて再生し、音量0の発音は除外する。素材にもドラムや低音があるため重ねる時は小さめに。クロスは左=A、右=B、中央=両方。
7. 「セットを保存」で名前付き下書きに、打点・音符・音色・BPM・全フェーダー・MUTE・素材のコード・AUTOと変奏seed/固定/採用前の軸、LIVEの流れ・間隔・盛り上がり・キープを残す。「保存版・バックアップ」→下書き一覧で復元。JSON持ち運びにも同じ保存コードが入る。再開は1小節目から。別のプリセットを選ぶ時は未保存編集を確認する。

PCはSpaceで開始/停止、1〜5でシーン、Escで全停止。入力欄・コード編集中はSpaceと数字を奪わない。停止後の再開は1小節目から。初回は音声処理の準備を待ってから開始し、準備待ち/打点変更直後のStopでも勝手に再開しない。

808風はサイン波の低音とpitch envelope、ノイズのスネア/ハット、金属的な合成カウベルによる**近似**。Roland純正のエミュレーションではない。追加音声ファイル・外部808バンク・有料pluginは不要。既存のオフライン音7本でセットと素材を使える。別画面のacidBrosは従来どおり独立した時計で、同時同期しない。

コード本文を直接編集した版でも、`const SET_MASTER = slider(...)`など接続が一つ残るフェーダーは使える。演奏中の全体音量・音色は数値だけ変え、本文やコメントを保つ。コードの変更は「コードを反映」。打点・展開・MUTEなど本文を生成し直す操作は無効になるため、戻す時はUndoか、先に保存してプリセットを選び直す。接続を削除・重複したフェーダーだけは無効になる。実PCの好み・出力音量、実iPhoneの操作/出音は本人確認。

演奏画面の上の「アプリ更新」で新しい版を確認して開き直せる。更新待ちがあれば「更新あり · 開き直す」と表示する。「ホーム画面・オフライン」にも同じ更新/再読込がある。再生中や未保存編集は先に確認し、保存済みの下書き・FILEは保つ。別タブが更新済みでも、この画面を再読込できる。旧版で上のボタンがない場合は下の「ホーム画面・オフライン」→「アプリを更新・再読込」。Ambient Driftがなければこの更新を試す。

人間とAIの協奏では、人間がフェーダー・打点・シーンを触り、AIが同じコードのフレーズや展開を編集する。現在は一つの画面とコードを共有する方式。AIのコード本文変更がセット形式を外れた場合は手動コードとして保存し、操作面へ戻すにはUndoか明示的なプリセット選択を使う。別ウィンドウ間の状態同期、チャット指示の自動受信、小節頭でのAI変更予約は未実装。

### 軸を守って変化させる（2026-10-01）

新しく開く4セットは`TECHNO_SET_V3`。軸の16ステップを4小節反復し、次の4小節は弱拍の1音または2音だけを隣の音へ動かす。休符と4つの強拍は変えず、8小節で軸へ戻る。章と16小節区間から次の候補を決め、軸へ変更を累積しない。同じseed/設定は同じ展開を再現する。Dub Roomの初期フレーズは強拍だけなので、音符の変奏は起こらず、音色とパートの抜き差しで変わる。

- 「音符を固定」は軸の音符を反復する。音色・アクセント・パート展開は続く。音色も固定するには「音色の起伏」を0にする。
- 「別の小変奏」はseedを進めて候補を変える。演奏中の表示が「小変奏 · 5〜8小節」の時、「今の変奏を残す」でそのフレーズを新しい軸にして固定できる。「採用前へ戻す」は一つ前の軸へ戻す。
- 303は低音の鋸歯波と高い矩形波の返しを同じclockで混ぜる。返しは低音に対する短3度/5度を共有スケールに絞り、数ステップだけ鳴らす。「303返し音量」とMUTEで出し入れする。左右固定ではない。
- 「303の2役・残響・音色の起伏」を開く。残響はテンポ同期の短いディレイ、音色は展開間の補間と展開間隔の2倍の呼吸で変わる。明るさ/起伏はパッドにも効く。スライド風は各音のpitch envelopeによる近似で、元303の発振器を継続するレガートとは違う。
- 「追加打楽器を出す」でCLAP / RIM / LOW・MID・HIGH TOM / CRASH / RIDEを選ぶと打点行が現れる。LIVEのタムは盛り上がりが標準以上の8小節目だけ、ブレイクでは抜く。クラッシュはブレイク後/山場の入口。音量/MUTEは一括。5音は合成、2シンバルは同梱済みacidBrosのWAVを再利用し、新しい音声は不要。

| 新セットの数字 | 範囲・上げるとどうなるか |
|---|---|
| CUTOFF（明るさ） | 120〜4800 Hz。明るく鋭くなる。音色の起伏と包絡も重なる |
| RESONANCE（みょん） | 1〜26。フィルターの共鳴が鋭くなる |
| DRIVE（歪み） | 0〜5。硬くザラつく |
| DECAY（うねりの長さ） | 0.03〜0.45秒。フィルターの動きが長く残る |
| RESPONSE（303返し音量） | 0〜40%。高い返しが前に出る。0で抜く |
| PERC（追加打楽器音量） | 0〜50%。選んだ追加打楽器が前に出る |
| SPACE（303の残響） | 0〜35%。短いディレイを増やす。0で消す |
| MOTION（音色の起伏） | 0〜100%。LIVEの展開と呼吸による明るさの変化が大きくなる。0で固定 |
| AIR（パッド音量） | 0〜65%。背景の長い三和音を重ねる。パッドMUTEで抜ける |

保存済みの`TECHNO_SET_V1/V2`は元のコード・音色・AUTOのまま読み込む。「この版からLIVE展開を作る」でだけ新形式へ移し、元の打点・音符・値・素材・MUTEを保つ。元の下書きも残るので、新しい名前で保存すれば比較できる。公開8試作の4小節コードも変更しない。

### やわらかく長めに聴く

[Ambient Driftを開く](https://music-private-live-workbench.pages.dev/?stage=ambient) →「セットを鳴らす」→「聴く画面」。76 BPM・32小節間隔で、長い三和音とフィルター/音量がゆっくり移る。「流れ」のアンビエントは自動ドラム/303を抜く。パッド音量とMUTEで背景の和音を調整でき、素材A/Bは手動音量が残るため、ドラム入り素材を足せばそのドラムは鳴る。

新しい音源・モデル・音声ファイルは増やさず、既存のStrudel合成を使う。自動展開はStrudelの音声時計に対する純粋関数で、定期的なコード書換えや再評価はしない。UIの章/展開表示も同じ規則と時計を使う。「聴く画面」は表示を畳むだけで、別プレーヤーや録音ファイルにはならない。スマホの画面ロック/他アプリ/車載出力での継続再生は端末依存で未確認。現状は開いたブラウザでの連続LIVEで、長時間の背景再生を保証しない。

### 元のacidBrosサイコロとAUTOの差

比較元は同梱v153の[Data.js](third_party/acidbros/js/data/Data.js)、[TB303.js](third_party/acidbros/js/audio/TB303.js)、[AudioEngine.js](third_party/acidbros/js/audio/AudioEngine.js)。全体のサイコロは次の関係をまとめて作る。

| 要素 | 元の全体サイコロ | 旧セットAUTO → 新セット |
|---|---|---|
| 2台の303 | 2号を低音、1号を上のフレーズにし、共有スケールと音程関係で組む | 1本の同じ16音 → 低音と疎な返し、4小節反復＋小変奏 |
| リズム | 低音は強拍優先、弱拍に同音反復。909は四つ打ちと裏拍に少量のフィル | パート出し入れとハット倍化 → 骨格を保持、フィルは8小節目だけ |
| アクセント/スライド | 発音に紐づけて生成、スライドは同じ発振器を続ける | 毎音ほぼ同じ → 強拍アクセントとpitch envelope近似 |
| 音色/空間 | 各303の波形・cutoff・共鳴・包絡・delayが独立 | 固定値 → 手動フェーダー＋ゆっくりしたcutoffの起伏・tempo delay |
| 気に入った版 | 303/909単位のLOCKとFILE保存 | 既存保存 → 音符固定、変奏採用/一段戻し、seed保存 |

2台は独立したTB303インスタンスで、同じ時計から共通のmaster compressorへ混ざる。LRに振り分ける処理はない。909の11パートはbd / sd / 3 toms / rim / clap / closed・open hat / crash / ride。元画面のMANAGE TRACKSで出し入れ、7種の合成音は歯車から編集し、自分のサンプル割り当てもできる。今回のStrudel版は役割を取り入れた近似で、元の全体サイコロや音色編集器をそのまま移植したものではない。

## 従来の試作・コードを使う

1. スマホまたはPCで入口を開く。PCのセット画面からは上の「試作・A/Bミックス」で一覧へ。スマホのrootは `aphex1`。`Acid 303 / 909` のハード版と初稿、`Techno 01・直進`、`Techno 02・余白`、`Auto Groove・毎周変化`、前の高速版と従来の4小節テストも一覧から選べる。
2. 最初に `Play` を押す。再生中に別の試作を選ぶと、コードを読み込んで演奏を切り替える。iPhoneでは最初の音声再生にタップが必要。停止中に選んでも音は勝手に鳴らない。
3. コードを変更したら `コードを反映` を押す。`Stop` ですぐ停止する。`選択中の版に戻す` で元コードへ戻る。
4. 気に入った編集は `この端末に保存` を押し、画面内の名前欄で下書きとして保存する。同じブラウザの下書き一覧からコードを戻せる。未保存のまま切り替える時は画面内で確認できる。読込待ちの間にさらに編集した場合も、置き換える前にもう一度確認する。キャンセルすると現在のコードと選択、演奏を保つ。
5. `Acid 303 / 909` を選ぶとコードの上に4本の縦フェーダーが出る。停止中もCUTOFF（明るさ）、RESONANCE（みょん感）、DRIVE（歪み）、DECAY（うねりの長さ）を調整でき、Playでその値から開始する。演奏中の数値はその場でコードにも残り、次の発音から反映される。元に戻すなら初稿を選ぶか「選択中の版に戻す」を押す。
6. コードの上の「この試作の音量」で、公開試作ごとに0〜100%の音量を合わせる。100%は元の音量、0は消音。Play中も動き、値はコードと**この端末のブラウザ**に試作ID別で残る。音を自動採点・均一化する機能ではなく、耳で合わせる。
7. ページ先頭の「2つの試作を組み合わせる」で公開試作をA/Bに選び、「組み合わせを開く」→Play。A/B音量と横のCROSSFADEを動かす。左端はAだけ、中央は両方、右端はBだけ。BはAのテンポに同期するので、違うBPMの2曲を元の速さのまま独立再生するDJデッキではない。気に入った組み合わせは「この端末に保存」でコードごと下書きへ残せる。`?deck=acid-303-909,techno-dub`のようなURLは公開試作の組み合わせを開くが、端末内の音量値は共有しない。
8. 上の「元の303×2＋909」、または「演奏面のつながり」→「切り替えて開く」で、`acidBros`の2台の303と11パートの909を同じページ内で開く。スマホなら「全画面で開く」が操作しやすい。Strudelの演奏は止まる。中の`RUN`で再生し、16ステップの打点と各つまみを触る。`FILE`で保存してから「閉じて停止」。直行URLは`/?module=acidbros`。StrudelのPlayやライブセット操作面へ戻るとacidBrosを閉じて停止する。
9. 303＋909で`FILE → SAVE`すると、試奏台の「この端末の303＋909パッチ」に名前と更新時刻が出る。名前は中のFILEで変更できる。パッチ名を押すとページ内に読み込み、隣の「全画面 ↗」ならスマホ向けの全画面でそのパッチを開く。読み込み前に現在の303＋909を停止する。未保存の調整がある場合は先にFILEで保存する。
10. 303＋909をページ内で開いた後、「StrudelのBPM → 303＋909」で現在選択中のコードのBPMを機械へ渡せる。逆の「303＋909のBPM → コード」は機械を閉じてStrudelコードの`setcpm`行だけを更新する。Playで聴き直し、残すなら「この端末に保存」。どちらもボタンを押した時だけの転送で、再生位置や音を同期しない。`setcpm`行が一つに定まらないコードでは転送ボタンを使えない。
11. 別の端末で続きを触るなら、試作一覧の下の「持ち運び・バックアップ」を開く。「保存済みをJSONに書き出す」でファイルを保存し、別の端末へ転送する。そちらの同じ欄でファイルを選び、名前・件数を確認して「この端末の一覧に追加する」。コードは下書き一覧、303＋909はパッチ一覧から選び直せる。公開ページとPCローカルの間でも同じ手順。

### 端末間で持ち運ぶもの

先にStrudelは「この端末に保存」、303＋909は中の`FILE → SAVE`。バックアップには**保存済みのコード下書き、作品別LEVEL、2デッキ設定、acidBrosのFILE**が入る。未保存のコードや303のつまみ・打点、演奏位置、音声ファイルは入らない。独自の音源を参照するコード・FILEでは、転送先にもその音源が必要。ファイルを自分で保存・転送する方式で、サーバーへアップロードしたり自動同期したりはしない。

読み込みは今ある保存版と設定を保って追加する。同じ保存版の再読込は件数を増やさず、異なる内容でIDが重なれば別IDにして両方を残す。既に設定のある作品・デッキには現在の端末の値を使い、未登録の設定だけ追加する。取り込んだ設定を使うには作品・組み合わせを開き直す。再生中のコードや303＋909の現在選択は追加操作では変更しない。

取り込んだ下書きは選択時にStrudelを止めてコードを開く。確認後にPlayまたは「コードを反映」で演奏する。JSONを選ぶ・一覧に追加するだけではコードを実行しない。303＋909も一覧から選び、RUNを押す。読み込み前にJSONの形式・件数・数値・FILEコンテナを確認し、容量不足などで保存が失敗した場合は先に書いたキーを戻す。

acidBros内の`FILE → EXPORT ALL`のJSONもここで読み込める。古いFILE形式で読めない場合は、303＋909のFILEで開いて保存し直してから書き出す。バックアップは8 MB以内、コードとFILEはそれぞれ500件まで。ブラウザの空き容量が足りなければ追加できない。実iPhoneのファイル保存・受け渡し操作は本人確認待ち。

### 音を変える・公開試作

フェーダーを上げるほど数字が大きくなる。CUTOFF（初期420 Hz、範囲120〜2200 Hz）は高いほど明るく鋭く、低いほどこもる。RESONANCE（初期18、1〜35）は高いほど「ミョン」という共鳴が鋭く、低いほど丸い。DRIVE（初期3.2、0〜7）は高いほど歪んでザラつき、低いほど澄む。DECAY（初期0.18秒、0.03〜0.5秒）は高いほどフィルターのうねりが長く、低いほど短く切れる。DECAYは音符自体の長さを変えない。まず1本だけ動かし、Stop後に「選択中の版に戻す」で基準値へ戻すと差が分かりやすい。

公開試作8件はGitの `src/library.json` と `src/patterns/*.txt` で版管理し、Pagesへ配信する。作品の日付ではなく、この試奏台へ登録した日付を一覧に表示する。`Techno 01` は124 BPM相当の4つ打ち、`Techno 02` は112 BPM相当で音数を減らす。`Auto Groove` は116 BPM相当で高音パートを確率的に間引き、8小節ごとにキックを一度抜く。これはStrudelのパターンによる自動変奏で、AIが音を聴いて生成しているわけではない。音の好みは本人試聴で判断する。

2デッキはStrudelの単一clockで2つのパターンを`xfade`し、作品内の各パートのgainを保ったまま作品全体のgainを掛ける。中央で両方が鳴るため合成後に0.7倍のheadroomを設けた。大きさの最終判定と実iPhoneでの同時再生負荷は未確認。旧形式の標準下書きには音量フェーダーを追加して開き、独自構造のコードは変更せずに開く。

`Acid 303 / 909` は128 BPM相当。ドラムはStrudel標準の `RolandTR909` バンクを参照し、未保存時は外部から読み込む。PWAで音を保存した後とPCローカル版では、キック・スネア・閉/開ハットの先頭サンプル4本を端末から読む。303風ベースは鋸歯波・共鳴ラダーフィルター・フィルターエンベロープ・歪みでブラウザ内合成する。初稿より共鳴、フィルターのうねり、歪みを強め、歪みの後で音量を抑える。このStrudel版で参照する909バンクはrepoへ複製しない。画面の縦フェーダーはStrudelのコード内スライダーを操作するので、変更値はコードに残り再評価なしで次の発音へ反映される。コード中の青いスライダーからも操作できる。初稿は別IDで残し、一覧で選べば元のコードに戻る。気に入った状態は「この端末に保存」で名前を付け、公開版へ採用する時はGitの試作コードとListenの入口を同じ変更で更新する。

## 303＋909ブラウザモジュール

`acidBros` v153を独立した画面として同梱した。2台の303は発振器→フィルター→ディレイをつまみで変え、909は11パートの16ステップと音色パラメータを触れる。これは**モジュラー風の制作入口**で、自由なケーブル配線やVST読み込みはまだない。Strudelの2デッキとは別の音声エンジン・時計・保存形式。FILE保存の一覧を同じoriginの試奏台から参照し、明示操作でBPMを双方向に転送する。連続BPM同期、パターンのコードへの自動変換、音声の内部ミックスはまだしない。切替時に前の演奏を止める。

同梱した909用WAVはハイハット・オープンハット・クラッシュ・ライドの4本、計438,798バイト。残りのドラムと303はブラウザ合成。外部サイトからこれらのWAVを毎回取得する必要はないが、初回は同じPages URLから読み込む。容量を小さくしたことが音声処理負荷やiPhoneのバックグラウンド再生を保証するわけではない。演奏中の各つまみの即時反映と端末上の保存を確認する。

`acidBros`の`FILE`保存は、その端末・そのブラウザの`localStorage`へ残り、Strudelの「この端末に保存」とは別。元のacidBrosサイトとの保存データも別。試奏台の保存一覧はこのacidBrosのFILEを参照する。別の端末には「持ち運び・バックアップ」のJSONを渡せる。`/modules/acidbros/?file=<ID>`はそのブラウザに既にあるFILEを選ぶ全画面URLで、他端末へパッチを渡す共有URLではない。単一パターンの共有にはacidBros内の`SHARE URL`も使える。公開版に採用するには、人の試聴後にこのrepoで更新する。上流版は自動更新されず、現在の出所・変更点・ライセンスは[`third_party/acidbros/UPSTREAM.md`](third_party/acidbros/UPSTREAM.md)を参照する。

## 人とComputer Useで一緒に触る

1. 人が音を聴きながらPlay、縦フェーダー、試作切り替えを操作する。同じブラウザ画面へComputer Useが接続できる場合は、AIもその画面の操作を手伝える。Stopは画面ですぐ押せる。
2. 「低音を短く」「909を少し薄く」など、聴感の要望をチャットで伝える。つまみだけで足りる変更は演奏中に操作し、ノート列・構成・音色の変更はコードを書き換えて「コードを反映」で試聴する。
3. 良い状態は「この端末に保存」で名前付き下書きにする。公開版に採用するコードと説明を選んだ後、Music repoの `src/patterns/`、`src/library.json`、Listen索引をまとめて更新し、チェックとデプロイを行う。

Computer Useの画面操作はその接続先の1ブラウザに限られ、スマホとPCの操作・音声・下書きは同期しない。チャットでのコード変更とGit/Pages更新には時間がかかるため、演奏中の即時操作はブラウザ内で行う。本人の聴感をAIが自動取得・採点する機能もない。

再生中の試作切り替えと、編集後の `コードを反映` はブラウザ内で演奏を更新する。GPT Liveとの直接接続、マイク・EP-133連動はまだ実装していない。

ブラウザ内で直したコードは自動で公開版へ同期しない。端末内下書きは `localStorage` に残り、別のスマホ・PCにはJSONバックアップで手動転送する。ブラウザの保存データを消すと下書きも消えるため、残す版はファイルにも書き出す。公開閲覧者にサーバーへの書き込み機能はない。

mainへのpush後はPagesのdeployment一覧を確認する。Git連携で新規buildが始まらない場合は、このディレクトリで`npm ci`、`npm run build`を実行し、`npx wrangler@4.129.1 pages deploy dist --project-name music-private-live-workbench --branch main`で同じ成果物を手動反映できる。Wranglerがローカル専用設定を無視する警告は意図どおり。

## スマホのホーム画面・オフライン

### ライブ中のフェーダー・BPM・スマホ音量

- 手動フェーダーは基準値。LIVE中はその下の小バーに、同じ演奏時計で計算した「展開後」の値を表示する。自動の抜き差しと明るさが見え、基準値を触ると追従する。小バーは音声を測るVUではなく、全体音量・音色・各発音の強弱より前の制御値。停止中・聴く画面・本文を手直しして生成形式が変わった版では表示しない。
- BPMは数字または横フェーダーで60〜180を操作する。演奏時計へ直接渡し、コードのmetadataと`setcpm`だけを書き換える。全コードの再実行や音源再取得はせず、既存フェーダーの接続・軸の音符・旧V1/V2/V3保存形式を保つ。「再生 ○ BPM」は実際の時計の値。打点／シーン変更は従来どおり必要なコード反映が入る。
- 保存するとBPMと手動基準値・自動展開の設定を残す。自動値を毎フレームcodeへ書く処理はない。表示は既存の80ms更新を使い、非表示のページと「聴く画面」では小バーを更新しない。実iPhoneの長時間負荷は未測定。BPMの自動加速は既定に追加しない。
- 上部の「音が出ない・端末の音量ボタンが効かない時」に、Strudel用の「音を再接続」を置く。初回のworklet初期化は一度だけ、再開時には既存AudioContextを毎回resumeする。ページへ戻った時の復帰も既に再生中の時だけで、停止した演奏を勝手に始めない。対応ブラウザでは`navigator.audioSession.type = 'playback'`を音楽再生時に指定し、未対応では通常のWeb Audioを使う。
- ページの音量、スマホのメディア音量、車の音量は別。出力先と物理ボタンの音量はOSと接続先が決めるため、ページから強制変更できない。iPhoneのコントロールセンターで再生先を選んだ後、無音なら再接続。復帰しなければ編集保存→アプリ再読込。acidBrosは別エンジンなので中のRUNを押し直す。実iPhone／Bluetooth／CarPlayでの物理音量ボタンと再接続は本人確認待ち。

根拠: [MDN Audio Session API](https://developer.mozilla.org/en-US/docs/Web/API/Audio_Session_API)、[AudioContextの中断と復帰](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state)、[Appleの出力先選択](https://support.apple.com/en-gb/guide/iphone/iph315e0d58d/ios)。API指定は端末の出力先を強制するものではなく、実機の問題が解消したとはまだ主張しない。

### ホーム画面へ追加・音を保存

1. [試奏台](https://music-private-live-workbench.pages.dev/)をiPhoneのSafariで開く。共有メニュー →「ホーム画面に追加」→「追加」。「Webアプリとして開く」があればオン。[Appleの手順](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)。AndroidはChromeのメニューから「アプリをインストール」または「ホーム画面に追加」。対応ブラウザでは画面内の追加ボタンも使える。
2. ホーム画面のアイコンから開く。「ホーム画面・オフライン」を開き、ネット接続中に「オフライン用の音を端末に保存」。**「オフライン準備OK」になるまで待つ**。
3. 機内モードなどで同じアイコンから開き直し、作品を選ぶ → Play。303＋909は「この中で開く」または「全画面で開く」→ RUN。自動では再生しない。
4. 編集は従来の端末内下書き/FILEへ保存。「更新あり」が出たら編集を保存して「アプリを更新・再読込」。更新を検出しただけで演奏を止めたり画面を開き直したりはしない。

アプリ本体/acidBrosの約6.7 MBと、公開3ループ＋固定909の4音の約3.2 MBを、このブラウザのCache Storageへ保存する。全7音の保存が成功してから新しい音源セットへ切り替え、失敗時は前の完全セットを残す。音を更新したい時はネット接続中に「保存した音を更新する」。Strudel版909の4音は外部の固定commit・SHA-256を検証し、**その端末だけに直接取得する**。MusicのGit/Cloudflare配布には追加しない。

ブラウザとホーム画面アプリで保存領域が別になる場合があるため、追加したアプリで準備する。下書き/FILEが見えなければ元ブラウザのJSONバックアップを持ち込む。サイトデータの削除やOSによる保存領域の整理で音が消えた時はネット接続中に再保存。PWAの保存は永続保存の保証ではない。大事なコード/FILEはJSONにも残す。PC/別端末への自動同期や画面ロック中の演奏保証はない。実iPhoneのホーム画面追加・機内モードの出音・長時間の保存維持は本人確認待ち。

### 音源の所在と追加方法

| 音 | どこから読むか | オフライン |
|---|---|---|
| Strudelの合成音・303、acidBrosの303と一部ドラム | ブラウザ内で合成 | アプリ本体の保存だけで使える |
| pad / sub / drums | 自分のCloudflare KV公開APIの3ループ | 音保存ボタンで端末へ取得 |
| Strudel標準909のキック/スネア/閉/開ハット | 外部の標準バンク | 固定版4音を音保存ボタンで端末へ取得 |
| acidBrosのハット/シンバル4本 | アプリ同梱のWAV | アプリ本体と一緒に保存 |
| コードに新しく指定した外部URLや他の標準バンク | その参照先から再生時に取得 | 自動では保存しない。ネット接続が必要 |

コードを保存しても、その中の音声ファイル自体は入らない。追加音源をオフラインに含めたい時は、対象URL・利用条件・容量・hashを確認して、必要な音だけ保存対象へ追加する。自前のループを公開する場合は管理者がKVとAPIの許可名を更新する。現画面には任意の音声アップロード機能はない。端末への保存は通信待ちを減らすが、音数・エフェクト・端末性能による処理負荷は別。

PWAのSWはこの独立Pages originだけに登録し、MusicのFM / Band Room / Core Rigとは別。build時に全静的ファイルのhashを生成し、混ざった配信世代をcacheしない。Pagesの`/index.html → /`転送はhash確認後のdecoded bodyからResponseを作り直し、転送flagと圧縮metadataを持たずに保存する。公開音源7本だけを明示保存し、private APIや未登録の外部URLはcacheしない。Safari等のWAV Rangeリクエストに206で返す。SW更新は下書き/FILEのlocalStorageを変更しない。

## PCでローカル起動・オフライン試奏

これはネイティブアプリではなく、**PC上のローカルHTTPサーバー＋Chrome/Edgeなどのブラウザ**で使う。同じ `Music` repo と同じ画面・公開8試作を使い、新しいrepoや常時接続のオンラインブラウザは要らない。`index.html`を`file://`で直接開く方法では、モジュールと音声APIの経路が成立しない。

初回だけネット接続中に、`experiments/workbench/v1` で次を実行する。

```powershell
cd C:\workspace\music-stack\Music\experiments\workbench\v1
npm ci
npm run local:prepare
```

これで固定版Strudelを含む画面をビルドし、公開中の3本のループとStrudel版アシッドで使う909の4音（計約3.2 MB）を `C:\Users\<ユーザー名>\.music-live-workbench\sounds` に保存する。909の4音はcommitを固定した公開標準バンクからその端末だけに取得し、Gitには追加しない。元サンプルrepoの再配布ライセンスは未確認のため、この機能では配布しない。保存後の起動と公開8試作の切り替えにはネット接続不要。

```powershell
npm run local
```

起動メッセージの `http://127.0.0.1:8788/` をPCのChrome/Edgeで開く。サーバーはPC自身からだけ開ける。終了は起動したターミナルで `Ctrl+C`。公開ページの音源や固定Strudel版を更新したい時だけ、ネット接続中に `npm run local:prepare` を再実行する。任意のポートは `MUSIC_WORKBENCH_PORT`、音源保存先は `MUSIC_WORKBENCH_SOUND_DIR` で変更できる。

ローカル版はStrudel起動時の標準音源一覧を端末内の小さな一覧へ差し替える。公開8試作に必要な3ループと909の4音は使えるが、**新しく書いたコードが他のStrudel標準サンプルや外部URLを参照する場合はオフラインでは鳴らない**。別のサンプルを使うにはオンライン公開版で試すか、必要な音を明示的に準備する。acidBrosの4 WAVは従来どおり画面と一緒にビルドされる。PCローカルとCloudflare公開URLは別originなので、ブラウザの下書き・音量・acidBrosのFILE保存は自動で共有されない。「持ち運び・バックアップ」のJSONで手動転送できる。スマホでは従来の公開URLを使い、PCの `127.0.0.1` には接続できない。

### OSS活用・更新と軽量化の方針（計画）

2026-10-01の本人方針は、既存OSSの音源を利用し、復元できる保管と更新の取り込み、より良い音源への部分的な差し替えを検討すること。音源の全面自作を既定工程にしない。自前部分は操作/コードの連動、作品の保存/索引、気持ちいい展開、軽量化を磨く。新しいrepoやページを既定の出口にしない。

StrudelとacidBrosは固定版を同じ配信へ同梱しており、上流サイトの停止だけで配信済みの版が止まる構成ではない。ただしGitだけでnpm依存とKV上の3ループを全復元できるわけではない。PWA cacheはOSによる削除もあるため永続バックアップとは扱わない。依存ソース/パッケージ・音源・ライセンスを復元可能な一式へ保管する整備は未完了。外部909音源の再配布条件は未確認で、repoへ追加しない。更新は試作・保存コードの互換性/出音を確認して取り込む。必要な音や挙動だけ独立実装する選択肢は残す。

無償公開は現在のAGPL版でも可能。「条件なし」への変更は別問題で、Strudelやその派生コードを単に改名・書き換えてMIT扱いにはしない。独立して作成した部分の公開条件は別途選べるが、MITの借用部分には著作権/ライセンス表示が必要。音源・フォント・画像もコードとは別に出所を確認する。現在のライセンス変更は行わない。

軽さは常時一つの音声エンジン、同時発音数の上限、残響/フィルター数の制限を軸に測る。現在はタブ非表示時の演奏面更新と、聴く画面で隠した打点の点滅更新を省き、表示中もステップが進んだ時だけ打点表示を変える。音の時計/パターン/自動展開は変えない。短いサンプル再生と合成音のどちらが軽いかは音源の実装次第。コード量やダウンロード容量だけで演奏中CPU負荷を判定しない。低負荷モードや同条件でのNamima比較、実iPhone測定はまだ未実装/未確認。
