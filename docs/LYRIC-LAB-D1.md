# Lyric Lab D1 sync

User workflow: [`LYRIC-LAB-USAGE.md`](LYRIC-LAB-USAGE.md).

Lyric Lab works locally with `localStorage` on GitHub Pages. Cloud sync is
optional and only turns on when deployed to Cloudflare Pages with a D1 binding.

## Cloudflare setup

1. Create a D1 database:

```bash
npx wrangler d1 create music-stack-lyric-lab
```

2. Copy `wrangler.example.toml` to `wrangler.toml` and replace
   `REPLACE_WITH_D1_DATABASE_ID` with the database id from Wrangler.

3. Apply the migration to the deployed D1 database:

```bash
npx wrangler d1 migrations apply music-stack-lyric-lab --remote
```

   Omit `--remote` only when testing against Wrangler's local D1 database.

4. Set a private Pages environment variable:

```text
LYRIC_LAB_TOKEN=<your shared sync token>
```

5. Deploy as Cloudflare Pages. The client calls `api/lyric-drafts` and sends the
   token in `X-Lyric-Lab-Token`.

## Data model

The D1 table stores one row per draft:

- `id`, `title`, `source_url`, `seed`
- JSON strings for settings and generated output
- `reroll`, `active_view`, `created_at`, `updated_at`

`result_json` may include a `scene` object generated by Lyric Lab. That object
is metadata only and must keep `no_lyrics: true`; it stores scene pressure,
image carriers, distance, risk flags, allowed/avoid moves, usable form, and
arrangement notes for later writing or Music Stack output decisions.

`settings_json` also carries optional UI controls such as direction, taste,
worldview, dialect, and the pasted `思想蒸留` intake text, so those features do
not require extra D1 columns.

Audio files are not uploaded or stored. Dropbox or Drive m4a links are saved as
source URLs only.

## Private cache boundary

The D1 shelf is authenticated private data, not a PWA asset:

- `functions/api/lyric-drafts.js` returns `Cache-Control: private, no-store`
  and varies responses on the authorization headers.
- `sw.js` must bypass every same-origin `/api/` request. It must never call
  `respondWith()` or `cache.put()` for the Lyric Lab endpoint.
- Service Worker upgrades may delete only caches with the Music-owned
  `hazama-fm-` prefix. Cache Storage is shared by origin, so deleting every
  unknown key would also evict chill / drum-floor / namima / openclaw caches.

Run `node scripts/check-cloudflare-pwa-contract.mjs` after changing the API,
Service Worker routing, authentication, or cache cleanup behavior.
