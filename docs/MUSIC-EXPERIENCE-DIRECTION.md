# Musicで育てる楽しさ

2026-10-28。これまでの本人の要望を、次の制作でも使える判断基準として整理したもの。
好みのモデル学習や自動作曲の完成を意味しない。新しい公開先は増やさず、Listenを使い続ける。

## 大切にする聴こえ方

- ロックのギターはストロークの立ち上がり、胴、ジャーンと伸びる響き。ベースは音程とボーンという芯。ドラムは打感と一発ごとの空気を両立する。
- 声と楽器が同じライブ空間にいること。分離のにじみを整えても、元の強弱と余韻を削りすぎない。声を遠くに隠すだけで解決しない。
- 原音は現存する仮ミックスを基準にする。調和ミックスは元の演奏を整えるもの、Dubは出し引き・反響・反復で展開を作るもの。AI再現は採譜と合成演奏として、別々に比較する。
- Dubではベースとドラムを土台に、声とギターが呼びかけて返す。音を止めるだけにせず、戻り方・間・反響の暗くなる過程まで一つのフレーズとして作る。
- Radiohead『OK Computer』やRHCPのような打感がロックの参考。将来のジャズは強弱、間、奏法、音程が揃ってから。特定作品を再現済みとは扱わない。

## 触って楽しいこと

触る → すぐ反応する → 手を離すと響きや小さな返事が残る。この順を見えるようにする。
常に密度を上げず、余白、休む手段、少しの意外性を残す。
スマホで始めやすく、止めやすく、次の一手が分かることを、演出より先に確かめる。
設定を一度に増やさず、一つの変化を楽しみ、気に入ったものを残す。

## 道具ごとの育て方

| 道具 | 楽しさの軸 | 次の改善を判断する基準 |
|---|---|---|
| Band Room / ARCB・Tabasco | ライブの一体感、比較、パートを抜いて演奏、Dubの展開 | 同じ箇所・近い音量で原音と比較。打点、音程、声の距離、自然な尾を確認 |
| 試奏台 / Core Rig | 反復と変化、固定と偶然、音を触って展開 | 一つ動かした結果が聴こえる。気に入ったパートを保てる |
| Hazama FM | 少ない操作で音の景色に浸る | 始動が軽く、長く聴いても疲れにくい。ラジオ自身の役割を保つ |
| drum-floor | リズムのポケットと身体性 | 拍の安定、停止後の無音、強弱とフィルのつながり |
| Namima | なぞる、音の返事、水と光の余韻 | 指の波紋とこだまを見分けられる。穏やかで家庭でも楽しめる |
| chill | ピアノと休符、静かな息づかい | 音数を増やすだけにしない。ベースとドラムは任意のまま |
| Lyric Lab / Desk | 良かった瞬間を残し、次の一手へ | 作品メモと設定を混同しない。Desk自身は発音・自動実行しない |

## 改善の進め方

まず現行を実際に見て、比較する箇所と変える要素を絞る。波形・周波数・ラウドネス・減衰などの
測定は破綻や差の説明に使う。数値合格だけで「いい音」「バンド再現できた」とは判定しない。
元の仮ミックスから存在しないマルチトラックを復元できたとも扱わない。
ブラウザ検証と実iPhoneの本人試聴を分けて記録し、次の本人の感想で基準を更新する。

現行の4つの遊び方と各アプリへのリンクは `config/music-stack-tools.json` で管理し、
同じrendererからListenとmanualへ表示する。ここは制作判断の基準、公開一覧の正本は既存Listen。
各アプリの役割を保ち、一度に変える要素を絞る。2026-10-28の本人指示により、通常の改善は必須検証後に既存本番へ公開し、PWAでの本人試聴を受けて調整する。

## 2026-11-08 — 過去の制作意図を、次に使える形へ統合

過去の本人発言の抜粋・検索要約、現行repo文書、保存済みの制作メモを照合した。
全チャットの全文移管や、全制作物の回収を終えた記録ではない。
次の一文は今回の編集上の統合案であり、本人の逐語引用や完成承認ではない。

**この世界を普通に生きる身体のために、余白と低音のある場を作り、声・楽器・コードで触り、気に入った瞬間を作品として育て続ける。**

### 音楽として残したい軸

| 軸 | 音と操作への翻訳 | 主な既存の担当 |
|---|---|---|
| 反復する床と身体性 | 低域の重心、休符、呼びかけと返事。声や楽器が乗る余地を残す | Music試奏台 / drum-floor / 既存VCV工程 |
| 静から動への連続性 | BPMだけでなく、音色・密度・明るさ・歪み・残響・変化量を扱う | Core Rig / 試奏台。各repoの音楽性は保持 |
| 手で変えられる演奏 | 一つを動かした結果が聴こえ、離した後に尾や返事が残る。固定と変奏を選べる | 試奏台 / EP-133等への既存の手渡し |
| 昔の自作曲から次の演奏へ | 原音を基準に、調和・Dub・新規再構成を比較。デモを育て、人の録り直しへ戻す | Band Room / 既存DAW工程 |
| 生活から言葉を作る | 具体物と行為から視点・時間の尺度を動かし、元の場所へ帰る。感謝と矛盾の両方を置く | Lyric Lab / 既存Scene OS |
| 暮らしと風景に返す | 穏やかな音の返事、水と光、ピアノと休符。家庭・庭・将来の展示へつなぐ | namima / chill / 既存の実験 |

本人の「この世界を、普通に生きる」という軸と、「ただそこにある感謝を掘る」という
問いを保持する。新しい熱や衝動が必要な時にも、昔の怒りを本人の現在として代筆しない。
言葉の核と距離感は[既存Lyric OS](lyric-os/okinawa-local/README.md)へ戻す。
観察から飛躍し、具体物へ帰還することは制作上の仮説として扱い、全作品の必須構成にしない。

「床」「歌もの」「ロック」「IDM」「静かなAmbient」は、それぞれ作品の目的に応じて選ぶ。
過去assistantが一つの試案に付けたキック禁止、展開禁止、特定BPMなどを、
本人の恒久的な制約へ広げない。言語の比率も作品ごとに決める。
namimaの穏やかさ、chillのピアノと休符、drum-floorのポケットは現在の役割どおり保持する。

### コードにする範囲

構造化した制作メモは
[制作意図JSON](examples/music-creative-intent.notes.json)。
既存の[session schema](schema/music-session-packet.schema.json)の
`music_intent`に対応する分類を使い、BPM、key、fader値、採用verdictは今回固定しない。
このファイルは説明用ノートであり、完全なsession packetや読み込み可能なpresetではない。
接続コードや自動実行を今回追加したものでもない。

| 残すもの | 目的 |
|---|---|
| 制作方針と意図 | 次のagentが何を作るかを読み取る |
| pattern / event / seed / recipeの参照 | 音を再開・変奏できる条件を残す |
| 既存work IDと親revision、変更点 | 元の作品から続きを辿れるようにする |
| 同じ試聴区間、本人の反応、計測の結果 | 音楽的採用と動作確認を区別する |

WAV、MIDI、コードが持つ編集能力と不足は[作品の出自ガイド](WORK-PROVENANCE-GUIDE.md)に従う。
元の音から存在しないマルチトラックや正確な採譜を復元できたことにはしない。
波形の計測と本人の聴感は別に記録する。

次の制作は、既存Listen / 作品棚から一つ開き、一つのパートを固定し、一要素を変え、
同じ区間・近い音量で比較して別版として残す。
実装作業の優先順位は[現行BACKLOG](autonomy/BACKLOG.md)で決め、
既存のpacket、adapter、試奏台、作品棚を再実装しない。

### 会話からrepoへ移した範囲

今回publicへ移すのは制作意図と再利用できる判断基準。
歌詞本文、私的なチャット原文、元会話の識別子、非公開作品の情報、実機の現配置は含めない。
個別作品の原文・編集稿と採用判断は既存privateノート / Lyric Lab、
実機の現状態はprivate music-opsに残す。

本人の今回の指示により、移行を確認できた過去の音楽チャットを順にアーカイブする。
要点の統合と、会話全文・添付・制作物の移行確認は異なる。
元チャットと保存先を照合し、実際の操作を確認した時点でのみ「アーカイブ済み」と記録する。
今回、全チャットの移管完了やアーカイブ操作の成功は主張しない。
