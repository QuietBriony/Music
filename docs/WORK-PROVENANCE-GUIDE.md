# ネタを理解して、続きを育てる

作業単位は「新しいアプリ」ではなく、**一つのネタと、その出自・元素材・改善先**。
全体の入口は[Music Stack manual](MUSIC-STACK-SYSTEM-MANUAL.md)。

## 三種類の「再現」を分ける

| やりたいこと | 必要なもの | 同じではないこと |
|---|---|---|
| 元と同じ音を再生成する | 元コードのrevision、入力hash、全設定、seed、音源/model版、環境 | seedだけ分かれば同一出力になるという保証 |
| 気に入った録音を磨く | WAV、可能ならパート別stems、元mixを残した別版 | MIDIの音符や元のつまみが自動復元されること |
| 自分で演奏・編集できる形にする | MIDI/pattern、gate、accent/slide、CC対応、音源preset、DAW project | 元データが失われた曲の完全な復元 |

元scriptが見つからず作り直す場合は「新規再構成」。使える音になっても、元の再現成功と
呼ばない。ファイル名のgenre、AIという語、WAVが鳴ったという事実だけで方式を推測しない。

## 一つの制作カードに必要な情報

1. **聴く**: 対象の版、試聴ファイル、比べる時刻。mixと骨格、比較リールを区別する。
2. **意図**: 何を残したかったか、前の版のどこを直したかったか。
3. **材料と方法**: 元の録音／自作合成／生成model、親素材、script・preset・request。
4. **確認の範囲**: メモにあるだけ、ソース確認済み、現物あり、再実行一致、本人の試聴を分ける。
5. **不足**: 元script、入力guide、パート別stem、MIDI、音源preset等。無いと断定せず検索範囲も残す。
6. **次に磨く場所**: 元の生成器、手続き合成、Sonar、公開制作のどの工程か。
7. **人の一言**: この版のこの区間で、残す点／直す点／次の一手。既存の判定を上書きしない。

採用判定は本人の記録。空欄は「判定記録なし」であって「未試聴」ではない。
短い比較クリップの方向選択、長尺版の完成承認、公開許可は別に扱う。

## 磨くシステムの選び方

| 残っているネタ | まず戻る場所 | Sonarの役割 |
|---|---|---|
| 手続き合成の骨格・ビート | 元scriptの音程、時間、密度、音色の設計 | stemsのバランス・構成。MIDIが出せれば音符も編集 |
| ACE等の生成音声 | 元prompt、入力guide、全生成設定 | 気に入った断片を使う、音数・長さ・余白を編集 |
| 音声＋MIDI＋DAW project | 元projectと対応する音源/preset | 別名保存から演奏・音色・編曲を続ける |
| 由来不明のWAV/M4A | まず保管場所と付随メモを照合 | 音声として使う候補。方式や権利を推測しない |
| 試聴リールや動画 | 抜粋元のpacketとcue sheet | 原本へ戻る道標。リール自体を原曲と扱わない |

Music Stackは道具の入口・探索・制作契約、Sonarは編集・演奏・仕上げ。
視覚的な8小節の楽器は[設計](VISUAL-COMPOSER-PLAN.md)段階であり、
既存ネタの全MIDI化や自動DAW往復が完了したという意味ではない。

## 元の生成器がある場合の、編集素材への出口

offline IDMについては[namima PR #40](https://github.com/QuietBriony/namima/pull/40)で
opt-inのパート別WAV出口を実装・検証しました（2026-09-08、human merge待ち）。
[取込手順](https://github.com/QuietBriony/namima/blob/8b9d0c20c6025632cea51c6915a1e70ca221fbd7/docs/idm-stem-export.md)から、
pad / lead / echo / sub / drums / texture / reverbをSonarの別音声トラックへ持ち込めます。
通常のmainへ導入済みとは扱わず、PWA・既定再生・既存納品catalogも変更しません。

- 「過去WAVを分離・復元」ではなく「同じ生成器から新たに編集候補を生成」。
- 7partはmaster前。共有残響は印刷済みで、各partのmuteやfaderに自動追従しません。
- premaster / masterの比較用WAVは重ねて鳴らさない。個別正規化もしません。
- 元コード・preset・設定・依存版・各file hash・未判定項目を同じpacketへ記録します。
- MIDI / .cwpではありません。音符と音色presetの編集、実Sonar取込・試聴は別工程です。

まず音声パートを引き算して、何が気になるかを言葉にする。
その後で元のpatternや音色設計を変えると、生成し直す目的を絞れます。
この実装の追跡は[BL-047](autonomy/BACKLOG.md)。個々の出力pathや作品名はpublicへ置きません。

同じPRの`namima.stem_compare`で、既存packetからA＝基準、B＝pad直接音を減らす、
C＝さらにecho / reverbを減らす、D＝さらにtextureをmute、という段階比較も作れます。
元の同じ区間をRMSでレベル合わせし、4つのフルWAV・比較リール・fader表・再実行planを保存。
任意で既存ffmpegによるM4Aを出力します。再合成、音符・タイミング変更、DAW操作はしません。
RMS一致は聴感合格ではありません。全版でノレないなら、次はmixでなく元patternを見直す判断材料にします。
この比較もhuman merge / 実試聴待ち。元の完成masterとのA/Bではなく、同じstemからのmix差です。

## 聴く入口を、そのPCの編集素材へつなぐ

制作カードにはクラウドの試聴リンクと、確認したPCのローカル保存先を併記する。
「Git内のノート」と「マイドライブに同期された表示」は別のパスなので区別する。
ローカルリンクが開かない閲覧環境のため、コピーできるフォルダ名とファイル名も残す。
実際のパス・host・非公開作品名はprivate側だけに置く。

- WAV: 音声を配置・加工する素材。音符・303のslide・音源presetが復元されるわけではない。
- MIDI: 音符を編集する素材。対応する音源、調律、音色の設定を別途確認する。
- DAW project: 外部音声・プラグインへの依存を確認し、元を残して別名保存から再開する。
- 元script: コードの所在と、当時の入力・設定・環境が揃っていることは別の確認。

ファイルの実在とbyte size一致は、内容hash一致・オフライン保存・実音の合格ではない。
別host、サイズ不一致、権限不足、通常ファイルでない場合は「確認済みで開ける」と表示しない。
初回は登録済みのファイル名だけを点検し、音声読込・再帰検索・自動再生・自動DAW起動をしない。

比較作業票には「対象packetと版／ファイル名／原曲上の区間／残す／直す／一つ変える点／
音声編集か再生成か新規再構成か／別名保存先」を書く。元素材を既に含む完成mixに同じ元素材を
二重に足さず、まず原速で交互に比較する。作業順の提案は採用判定や公開許可と区別する。

## 正本と非公開の境界

- 道具の説明・汎用workflow: public Music。
- 既存の納品catalogと本人のverdict: 既存のprivate納品レーンを維持。
- 実際の保存先・非公開作品の由来・回収待ち: optional private `music-ops/works/README.md`。
  元catalogを読む補助記録にし、判定台帳をもう一つ作らない。
- 音声・MIDI・DAW project: Git外。元を移動・削除・上書きせず、採用版を別に残す。
- 機材の所有・実配線・現在のPC: private music-opsの既存canonical JSON。
- 投稿の履歴と現在の公開状態: 担当工程で別に確認。制作メモの「投稿予定」を公開済みとしない。

private overlayがない環境では個別作品の一覧・host・Driveリンクを推測せず、この汎用手順だけ使う。
非公開の曲名、exact path、個人のDriveリンクをこのpublic文書へ追加しない。

## 次の進め方

既存の試聴棚で一つ選ぶ → 出自カードの不足を埋める → 元データを保全する →
一項目だけ変えた候補を作る → 本人が同じ区間で比較する。

初回の棚卸しだけで音源の採用、権利確認、実機検証、公開まで完了したとは扱わない。
